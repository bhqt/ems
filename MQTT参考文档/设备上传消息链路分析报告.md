# 设备上传消息到平台处理，到大屏展示 - 完整链路分析报告

## 报告概述
本报告详细分析了祝融能源管理系统中，设备上传消息到平台处理，最终在大屏展示的完整数据链路逻辑实现情况。

## 完整数据链路架构

```
设备 → MQTT Broker → 后端服务 → RabbitMQ → 数据存储 → 后端API → 前端展示
```

## 1. 设备数据上传层

### 1.1 MQTT协议通信
- **协议**: MQTT (Message Queuing Telemetry Transport)
- **Broker**: EMQX 5.3.2
- **连接配置**:
  - 主机: tcp://zhurong-ems-emqx:1883
  - 用户名: admin
  - 密码: public
  - 客户端ID: zhurong-ems-server-${HOSTNAME:-default}
  - 超时时间: 120秒
  - 心跳间隔: 360秒

### 1.2 支持的MQTT主题
系统支持以下主题进行设备数据上传：

1. **电表综合数据**: `electric/emsCarson`
2. **电表所有数据**: `electric/all/{clientId}`
3. **电压数据**: `electric/voltage/{clientId}`
4. **电流数据**: `electric/current/{clientId}`
5. **电能数据**: `electric/consumption/{clientId}`
6. **功率数据**: `electric/power/{clientId}`
7. **水表数据**: `water/consumption/{clientId}`

### 1.3 数据格式
设备上传的数据格式为JSON，包含以下字段：
- `clientId`: 设备唯一标识
- `value`: 测量值
- `deviceType`: 设备类型（用于electric/all主题）
- `createTime`: 时间戳（可选，系统会自动补充）

## 2. MQTT消息接收与处理层

### 2.1 MQTT客户端实现
**文件位置**: `zhurong-ems-system/src/main/java/com/ruoyi/system/config/MyMQTTClient.java`

**核心功能**:
- 自动重连机制：连接断开后自动重连
- 消息发布：支持向指定主题发布消息
- 主题订阅：支持订阅多个主题
- 连接状态监控：实时监控MQTT连接状态

### 2.2 MQTT回调处理
**文件位置**: `zhurong-ems-system/src/main/java/com/ruoyi/system/config/MyMQTTCallback.java`

**处理逻辑**:

1. **连接成功处理**:
   - 自动订阅所有相关主题
   - 支持重连和直连两种方式

2. **消息接收处理**:
   - **电表综合数据** (`electric/emsCarson`):
     - 解析JSON数据
     - 自动补充createTime字段
     - 转发到RabbitMQ的`ELECTRIC_emsCarson`主题

   - **电表所有数据** (`electric/all/{clientId}`):
     - 解析JSON数组
     - 根据deviceType匹配目标主题
     - 分别转发到对应的RabbitMQ主题

   - **电压数据** (`electric/voltage/{clientId}`):
     - 解析JSON数据
     - 转发到RabbitMQ的`ELECTRIC_U`主题

   - **电流数据** (`electric/current/{clientId}`):
     - 解析JSON数据
     - 转发到RabbitMQ的`ELECTRIC_I`主题

   - **电能数据** (`electric/consumption/{clientId}`):
     - 解析JSON数据
     - 转发到RabbitMQ的`ELECTRIC_W`主题

   - **功率数据** (`electric/power/{clientId}`):
     - 解析JSON数据
     - 转发到RabbitMQ的`ELECTRIC_P`主题

   - **水表数据** (`water/consumption/{clientId}`):
     - 解析JSON数组
     - 转发到RabbitMQ的`WATER_CONSUMPTION`主题

3. **连接断开处理**:
   - 自动重连机制
   - 5秒重连间隔
   - 无限重连尝试

### 2.3 时间戳自动补充
系统会自动为没有createTime字段的数据添加当前时间戳，格式为：`yyyy-MM-dd HH:mm:ss`

## 5. 后端API服务层

### 5.1 能源统计API
**Controller**: `com.cpems.web.controller.energy.EnergyController`

**关键接口**:

1. **今日用能统计**
   - 路径: `/data/energy/getConsumptionStatistics`
   - 方法: GET
   - 参数: `areaId` (区域ID)
   - 返回数据:
     - `electricity`: 今日用电量
     - `kgce`: 综合能耗
     - `kg`: 碳排放量

2. **今日能源趋势和碳排放量**
   - 路径: `/data/energy/getTrendAndCarbon`
   - 方法: GET
   - 参数: `areaId` (区域ID)
   - 返回数据:
     - `trendResult`: 24小时综合能耗趋势
     - `carbonResult`: 24小时碳排放趋势

3. **设备状态统计**
   - 路径: `/equipment/getAllStatus`
   - 方法: GET
   - 返回数据:
     - 正常设备数量及占比
     - 报警设备数量及占比
     - 离线设备数量及占比

### 5.2 能源服务实现
**Service**: `com.ruoyi.system.service.impl.EnergyServiceImpl`

**核心业务逻辑**:

1. **getConsumptionStatistics方法**:
   - 根据区域ID查询关联设备
   - 查询今日能耗统计数据
   - 计算综合能耗：电能耗/8.167 + 水能耗*0.4857
   - 计算碳排放量：电能耗*0.785 + 水能耗*0.91

2. **getTrendAndCarbon方法**:
   - 查询今日24小时能耗数据
   - 按小时分组统计
   - 计算每小时的综合能耗和碳排放量
   - 返回24小时的趋势数据

3. **getAllStatus方法**:
   - 查询所有设备总数
   - 分别统计正常、报警、离线设备数量
   - 计算各状态设备的占比

### 5.3 设备服务实现
**Service**: `com.ruoyi.system.service.impl.EquipmentInfoServiceImpl`

**核心业务逻辑**:

1. **getAllStatus方法**:
   - 查询设备总数
   - 按状态分组统计设备数量
   - 计算各状态设备的占比
   - 返回设备状态统计信息

## 7. 数据流转详细分析

### 7.1 设备数据上传流程
1. 设备通过MQTT协议连接到EMQX Broker
2. 设备按主题格式发布数据到对应主题
3. MQTT Broker接收并转发给订阅的后端服务

### 7.2 后端消息处理流程
1. MyMQTTCallback接收MQTT消息
2. 解析JSON数据，补充时间戳
3. 根据主题类型转发到对应的RabbitMQ队列
4. RabbitMQ保证消息可靠传输

### 7.3 数据存储流程
1. 消息消费者从RabbitMQ队列获取消息
2. 解析消息内容，提取设备编号、时间、数值等信息
3. 存储到energy_statistics表
4. 更新设备状态信息

### 7.4 数据查询流程
1. 前端调用后端API接口
2. 后端根据区域ID查询关联设备
3. 从energy_statistics表查询能耗数据
4. 计算综合能耗和碳排放量
5. 返回格式化的数据给前端

### 7.5 前端展示流程
1. 页面加载时调用API获取数据
2. 接收后端返回的JSON数据
3. 更新页面状态变量
4. 通过图表组件渲染数据
5. 实时展示能耗趋势和设备状态

## 9. 潜在问题分析

### 9.1 前端API路径问题
**问题描述**: 前端调用的API路径与后端实际路径不匹配

**影响**: 大屏数据无法正常加载

**解决方案**: 已修复前端API路径配置，确保路径匹配

### 9.2 数据缺失问题
**问题描述**: 大屏显示今日用能统计、设备状态、今日能源趋势、今日碳排放量无数据

**可能原因**:
1. 设备未正常连接MQTT Broker
2. 数据未正确存储到数据库
3. 区域ID配置不正确
4. 设备未关联到对应区域

**排查建议**:
1. 检查MQTT连接状态
2. 检查RabbitMQ消息队列状态
3. 检查数据库中是否有能耗数据
4. 检查设备区域关联配置

### 9.3 消息处理延迟
**问题描述**: 设备数据上传到前端展示存在延迟

**可能原因**:
1. MQTT消息处理队列积压
2. 数据库写入性能瓶颈
3. 前端数据刷新频率过低

**优化建议**:
1. 增加消息处理消费者数量
2. 优化数据库索引和查询
3. 提高前端数据刷新频率
