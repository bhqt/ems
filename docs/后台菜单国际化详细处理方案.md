### 1.2 核心问题

**后台菜单数据的来源与翻译策略不明确**：

1. **方案A**：后端存储中文名称，前端通过映射表翻译
2. **方案B**：后端存储国际化key（如 `menu.system.user`），前端直接翻译
3. **方案C**：后端存储多语言JSON字段，前端按语言选择

## 二、推荐方案：混合模式

### 2.1 方案设计

采用 **国际化Key + 前端映射表** 的混合模式：

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│   数据库存储     │ ──▶ │   后端返回      │ ──▶ │   前端翻译      │
│  menuName       │     │  menuName       │     │  menuName       │
│  (中文或key)    │     │  (原始值)       │     │  (通过映射表)   │
└─────────────────┘     └─────────────────┘     └─────────────────┘
```

#### Step 2: 优化 `helper.js` 翻译逻辑

```javascript
// 翻译菜单标题
export function translateMenuTitle(title, fallback = '') {
  if (!title) return ''
  
  // 1. 如果是国际化key格式（包含点号），直接翻译
  if (title.includes('.')) {
    const translated = i18n.t(title)
    if (translated !== title) {
      return translated
    }
  }
  
  // 2. 尝试构建key路径进行翻译
  const possibleKeys = buildPossibleKeys(title)
  for (const key of possibleKeys) {
    const translated = i18n.t(key)
    if (translated !== key) {
      return translated
    }
  }
  
  // 3. 返回原始文本或回退值
  return fallback || title
}

// 构建可能的key列表
function buildPossibleKeys(title) {
  return [
    `menu.${title}`,
    `menu.system.${title}`,
    `menu.monitor.${title}`,
    `menu.tool.${title}`,
    `menu.energy.${title}`,
    `menu.equipment.${title}`,
    `menu.alarm.${title}`,
    `menu.charging.${title}`,
    `menu.inspection.${title}`,
    `menu.hazardous.${title}`,    // 危化品模块
    `menu.itemized.${title}`,
    `menu.dataQuery.${title}`,
    `menu.profile.${title}`
  ]
}
```

## 四、后端菜单数据国际化策略

### 4.1 方案选择

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **方案A: 前端映射** | 后端改动小 | 需维护映射表 | 现有系统改造 |
| 方案B: 存储key | 简单直接 | 后端需存储多语言key | 新系统开发 |
| 方案C: 后端多语言 | 灵活 | 后端改动大 | 大型系统 |

**推荐方案A**：前端通过 `helper.js` 中的映射逻辑翻译，后端保持存储中文名称。

### 4.2 后端配合事项

1. **不改数据库**：菜单名称字段保持存储中文或其他原始语言
2. **不改接口**：后端 `getRouters` 接口保持原样返回 `menuName`
3. **前端处理**：前端通过 `translateMenuTitle()` 函数在渲染前翻译

### 4.3 扩展：支持后端返回key格式

如果未来需要后端支持国际化key，可以：

1. 后端在菜单表中增加 `menuNameEn`、`menuNameRu`、`menuNameId` 字段
2. 或者增加 `i18nKey` 字段存储国际化key
3. 前端根据用户语言设置选择对应字段或使用key
