## 1 部署目标与范围

### 1.1 部署目标

在客户机房（或指定服务器）完成 V4.6.0 平台的安装部署，实现：

1. 后端服务 `zhurong-ems-admin`（Spring Boot 2.7.9 单体内嵌 Undertow）正常运行，端口 **8088**，上下文路径 **/autoee-iot-ems**；
2. 前端 `zhurong-admin-ui`（Vue 2 + Element UI）经 Nginx 托管，浏览器通过 **http://服务器IP/** 访问；
3. MySQL、Redis、RabbitMQ、EMQX 四类必选中间件以 Docker Compose 方式运行；TDengine 为可选时序库（默认关闭，按需启用）；
4. 设备 MQTT 数据链路（设备 → EMQX → 后端 → RabbitMQ/MySQL/TDengine）打通；
5. 医院 IOT 平台回调链路（IOT 平台 → Nginx/后端 `/hospital/callback/data`）调通；
6. XXL-Job 调度中心、Spring Boot Admin 监控等配套组件部署到位；
7. 默认口令全部修改、端口按最小化原则开放、备份策略生效。

### 1.2 部署范围

| 范围内 | 范围外 |
|---|---|
| 后端、前端、5 类中间件、XXL-Job、Spring Boot Admin | 服务器硬件采购、机房网络综合布线 |
| 数据库 `autoee_ems` 初始化、医院模块加性脚本、菜单脚本 | 客户侧 IOT 平台自身改造（仅提供对接配置） |
| Nginx 反向代理、HTTP 访问（HTTPS 为加固可选项） | 第三方堡垒机、VPN、等保测评设备 |
| MQTT 设备接入联调（含 simulator 模拟） | 真实电表/水表设备的现场安装与调试（由设备厂商负责，平台侧配合） |
| 备份策略配置与一次恢复演练 | 长期容量规划与异地容灾建设 |

### 1.3 部署原则

- **只增不改**：生产部署脚本 `docker-compose-54.yml`（192.168.8.54 现网脚本）**必须保持原样，严禁修改**；环境差异通过环境变量、外挂配置文件或新建 compose 文件解决。
- **配置与程序分离**：所有环境相关参数（IP、口令、vhost）通过 `application-{profile}.yml`、环境变量或 Nginx 配置注入，不将生产口令写入代码仓库。
- **先备份后变更**：任何升级/割接操作前先完成数据库与配置备份。
- **最小权限、最小端口**：中间件端口默认不对外，仅 80（及 443）、MQTT 必要端口对外开放。
- **可回退**：每次上线保留上一版本 jar/镜像/dist 与数据库备份，保证可在约定时间内回退。

## 2 部署架构

### 2.1 总体架构

采用**前后端分离 + Nginx 反向代理 + Docker Compose 中间件**架构：

- 浏览器/移动端 → Nginx（80 端口）：静态资源直接返回，`/prod-api/`、`/autoee-iot-ems/` 反向代理至后端 8088；
- 后端为 Spring Boot 2.7.9 单体（内嵌 Undertow），对外 REST API，对内消费 MQTT/AMQP；
- 设备/模拟器 → EMQX（1883/8883）→ 后端 MQTT 客户端订阅 → 业务处理 → RabbitMQ 异步解耦 → MySQL（业务库）/TDengine（高频时序，可选）；
- 医院 IOT 平台 → Nginx → 后端回调接口（Token/IP 白名单/签名鉴权）；
- 运维侧：Spring Boot Admin 监控后端 JVM，XXL-Job 调度中心负责任务调度。

## 3 服务器与资源规划

### 3.1 硬件配置

| 规模 | CPU | 内存 | 系统盘 | 数据盘 | 适用场景 |
|---|---|---|---|---|---|
| 最低（POC/演示） | 4 核 | 8 GB | 100 GB SSD | 与系统盘同盘 | 单节点全容器、设备 < 100、演示 |
| 推荐（单机房生产） | 8 核 | 16 GB | 100 GB SSD | 200 GB SSD 独立挂载 `/data` | 设备 500~2000、日消息量百万级 |
| 扩容（多院区/高负载） | 应用节点 4C8G + 中间件节点 8C16G 起 | — | — | TDengine/MySQL 独立盘 | 设备 > 2000 或消息量 > 千万/日 |

容量估算参考：单条设备消息约 0.5~1 KB；仅入 MySQL 时每千万条约 5~10 GB；启用 TDengine 高频落库时按点位数 × 采集频率 × 保留天数单独测算（TDengine 压缩比通常 5~10 倍）。

### 3.2 软件版本要求

| 软件 | 版本要求 | 说明 |
|---|---|---|
| 操作系统 | CentOS 7.9 / 麒麟 V10 / Ubuntu 22.04（x86_64） | 生产建议与现网一致；统一时区 Asia/Shanghai |
| JDK | **JDK 1.8（强制，8u371 以上推荐）** | 编译/运行均以 1.8 为目标；**不兼容 JDK 17+ 直接启动** |
| Maven | 3.8+（构建机） | 产物 `zhurong-ems-admin.jar` |
| Node.js | 16/18/20（构建机；前端镜像使用 node:20） | 需支持 `--openssl-legacy-provider`（Node 17+ 必须） |
| Docker Engine | 24.0+ | 含 Docker Compose V2（`docker compose`） |
| Docker Compose | v2.20+ | 旧版 `docker-compose` v1 亦可，命令相应替换 |
| Nginx（非容器部署时） | 1.24+ | 容器形态镜像为 nginx:1.28.3-alpine |
| 浏览器 | Chrome 100+/Edge 100+ | 平台不支持 IE |

> **JDK 兼容性强约束**：若因客观条件只能使用 JDK 17/21 启动，**必须**在启动命令中追加 7.2 节列出的 10 项 `--add-opens` 参数，否则所有页面报“系统内部错误”（HTTP 500，异常 `InaccessibleObjectException`）。生产仍**强烈建议使用 JDK 1.8**。

### 3.4 用户与权限

```bash
# 创建专用运行用户（加入 docker 组以便管理容器；生产可改用 sudo 白名单收紧）
groupadd -r ems && useradd -r -g ems -m -d /opt/zhurong-ems -s /bin/bash ems
usermod -aG docker ems
chown -R ems:ems /opt/zhurong-ems /data/ems
# 后端服务禁止以 root 运行（容器内镜像默认 root 的，应在编排中追加 user: "1001:1001" 或由宿主机 umask 控制）
```

- 数据库、Redis、RabbitMQ、EMQX 均为应用自建专用账号，禁止应用直接使用 root/管理员账号；
- 服务器关闭无关账号，配置 sudo 审计；SSH 建议密钥登录并限制来源 IP。

### 3.5 系统级初始化

```bash
timedatectl set-timezone Asia/Shanghai          # 时区（签名/回调强依赖时钟一致）
systemctl enable --now chronyd && chronyc makestep   # 时间同步（时钟漂移会导致签名失败）
systemctl disable --now firewalld 2>/dev/null || true   # 若使用云安全组可关闭本机 firewalld；否则按第 4 章放行
sysctl -w vm.max_map_count=262144               # 部分中间件（ES 类）需要；预先设置无副作用
echo "* soft nofile 65535; * hard nofile 65535" >> /etc/security/limits.conf
```

### 5.2 启动自研全栈中间件（推荐全新环境）

前置：Docker Engine 与 Compose V2 已安装并启动；`docker run hello-world` 正常。

```bash
# 1) 准备目录（以仓库根目录或 /opt/zhurong-ems/compose 为工作目录）
cd /opt/zhurong-ems/compose
# 将仓库根目录 docker-compose.yml、docker/ 目录、数据库脚本/ 目录放置到对应相对路径
# compose 内挂载：./数据库脚本:/docker-entrypoint-initdb.d、./docker/tdengine/init.sql 等

# 2) 拉取镜像（离线环境改为 docker load -i 镜像包）
docker compose pull

# 3) 启动全部中间件
docker compose up -d

# 4) 查看状态与健康检查（全部 Up、healthy 后再继续）
docker compose ps
docker compose stats --no-stream
```

逐服务核对（与 `docker-compose.yml` 保持一致）：

| 服务 | 镜像 | 关键环境变量 | 卷 | 健康检查 |
|---|---|---|---|---|
| zhurong-ems-mysql | mysql:8.0.35 | `MYSQL_ROOT_PASSWORD=123456`、`MYSQL_DATABASE=autoee_ems`、`TZ=Asia/Shanghai`；启动参数 utf8mb4 / utf8mb4_unicode_ci / `max_connections=1000` | `zhurong-ems-mysql-data:/var/lib/mysql`、`./数据库脚本:/docker-entrypoint-initdb.d`、`./docker/mysql/conf:/etc/mysql/conf.d` | `mysqladmin ping -uroot -p123456` |
| zhurong-ems-redis | redis:7.2.3-alpine | 配置以 `./docker/redis/redis.conf` 为准（挂载到 `/etc/redis/redis.conf`） | `zhurong-ems-redis-data:/data` | `redis-cli ping` |
| zhurong-ems-rabbitmq | rabbitmq:3.12-management-alpine | `RABBITMQ_DEFAULT_USER=guest`、`RABBITMQ_DEFAULT_PASS=guest` | `zhurong-ems-rabbitmq-data:/var/lib/rabbitmq` | `rabbitmq-diagnostics ping` |

#### 5.5.2 升级/使用 TDengine 3.3.6.13 的硬约束（重点）

1. **密码复杂度**：3.3.6.13 强制口令必须包含**大写字母 + 小写字母 + 数字/特殊字符**。`difyai123456`（纯小写+数字）不满足复杂度，必须更换，例如 `Difyai@2026`（示例，现场自定义并记入密码本）。
2. **不支持 `CREATE USER IF NOT EXISTS`**：3.x 正确语法为 `CREATE USER energy PASS '口令';`；用户已存在时报 `User already exists`，跳过即可（先 `SHOW USERS;` 判断）。
3. **不要使用 `TAOS_ROOT_PASSWORD` 覆盖 root 密码**：首次以默认口令登录后，用 `ALTER USER root PASS '新复杂口令';` 改密。
4. **不要给容器自定义 `command`**：3.3.6.13 内置 entrypoint 已负责初始化与启动，自定义 command（如旧编排里的 `sh -c "sleep 15 && taos -s ... && taosd"`）会与 entrypoint 冲突，导致初始化异常。
5. 仓库内 `docker/tdengine/init.sql` 使用了 `CREATE USER IF NOT EXISTS ... WITH PASSWORD` 语法，**在 3.3.6.13 上会执行失败**，因此 3.3.6.13 一律采用**手动初始化**（容器健康后手工执行 SQL），不要依赖挂载脚本。
6. 保留字坑：`value` 为 TDengine 保留字，医院超表数值列已命名为 `metric_value`（见 `数据库脚本/hospital_init_tdengine.sql`）；新增脚本不得使用保留字做列名，历史对象重命名用 `数据库脚本/hospital_rename_reserved_words.sql`。

3.3.6.13 手动初始化序列（示例口令 `Difyai@2026`，请替换）：

```bash
docker exec -it zhurong-ems-tdengine taos -u root -p<默认/当前口令>
# taos CLI 内：
ALTER USER root PASS 'Difyai@2026';
CREATE DATABASE IF NOT EXISTS energy KEEP 365 DURATION 10 BUFFER 16;
CREATE USER energy PASS 'Energy@2026';
GRANT ALL ON energy TO energy;
SHOW DATABASES; SHOW USERS;
```

### 8.3 nginx.conf 关键配置要点

仓库 `zhurong-admin-ui/nginx.conf` 已含完整配置，裸机部署按下述要点核对（容器名按实际替换为 upstream 主机）：

```nginx
server {
    listen       80;
    server_name  _;
    root   /opt/zhurong-ems/frontend/dist;
    index  index.html;
    charset utf-8;
    access_log /var/log/nginx/ems_access.log;
    error_log  /var/log/nginx/ems_error.log;

    # 静态资源强缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
        expires 1y; add_header Cache-Control "public, immutable";
    }

    # 生产 API：/prod-api/ → 后端 context-path（注意末尾斜杠映射）
    location ^~ /prod-api/ {
        proxy_pass http://127.0.0.1:8088/autoee-iot-ems/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_connect_timeout 60s; proxy_send_timeout 60s; proxy_read_timeout 60s;
    }

    # 直连 context-path（医院回调 /autoee-iot-ems/hospital/callback/data 走此段）
    location ^~ /autoee-iot-ems/ {
        proxy_pass http://127.0.0.1:8088/autoee-iot-ems/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # SPA 路由回退（防止刷新 404）
    location / { try_files $uri $uri/ /index.html; }

    location /health { access_log off; return 200 "healthy\n"; add_header Content-Type text/plain; }
    location ~ /\. { deny all; }
}
```

gzip 建议（构建已用 CompressionPlugin 生成 `.gz` 预压缩文件，Nginx 可直接启用）：

```nginx
gzip on;
gzip_min_length 1k;
gzip_comp_level 6;
gzip_types text/plain text/css application/json application/javascript text/xml application/xml application/xml+rss text/javascript image/svg+xml;
gzip_vary on;
gzip_static on;   # 优先返回 dist 中现成的 .gz 文件（需 nginx 含 http_gzip_static_module）
```

## 12 安全加固

1. **默认口令全部修改**：MySQL root/123456、Redis（difyai123456）、RabbitMQ guest/guest、EMQX admin/public 与 TDengine root 口令、XXL-Job accessToken（default_token）、Spring Boot Admin（admin/zhurong123）、平台 admin/123456、`hospital.iot.auth-token`（hospital-iot-2026）。
2. **HTTPS**：Nginx 配置证书（443，TLS1.2+），80 跳转 443；MQTT 可用 8883 证书；证书到期纳入监控（提前 30 天告警）。
3. **最小端口**：按第 4 章收敛安全组，3306/6379/5672/6030/6041 不对用户网与设备网开放，15672/18083/9110/8690 仅运维网段。
4. **账号最小权限**：应用不用中间件管理员账号；MySQL 只授 autoee_ems 库权限；RabbitMQ 按 vhost 授权；EMQX 按主题前缀授权；Sa-Token 已配置 Bearer/Authorization 头、15 天有效期（可按需调短）。
5. **备份**：见运维手册数据备份章节；备份文件异机保存并定期恢复演练。
6. **其他**：开启操作日志（sys_oper_log）与登录日志；XSS 过滤已启用；关闭 Swagger 公网访问（生产 springdoc.api-docs.enabled 可按客户要求关闭）；服务器定期补丁；防病毒/主机安全 Agent 按客户规范安装。

## 14 割接、灰度与回退概述

- **割接策略**：优先选择业务低峰窗口；设备侧先在测试主题/少量设备灰度（EMQX 按 clientid/主题分批切换），观察 30 分钟无积压后全量切换。
- **灰度方式**：
  1. Nginx  upstream 双后端（旧版本 + 新版本）权重 9:1 → 5:5 → 全量（注意 Sa-Token 会话与 Redis 共享，两版本须共用同一 Redis/db）；
  2. 或按院区/部门分批放量（前端入口不变，后端按请求头/IP 分流）。
- **回退概述**（详细步骤、触发条件见 [05-03 上线检查与回滚方案](05-03%20上线检查与回滚方案.md)）：
  - 后端：systemd 切回 `.bak` 旧 jar 重启；容器切回旧镜像 tag（`zhurong-ems/backend:<旧tag>`）；
  - 前端：dist.bak 回滚或镜像切旧 tag，reload Nginx；
  - 数据库：加性脚本为主（IF NOT EXISTS），回退用预先准备的反向脚本；结构破坏性变更用 T-1 全量备份恢复；
  - 消息：RabbitMQ 堆积消息不清理，回退后由旧版本继续消费；必要时按 msgId 对账补偿；
  - TDengine：仅追加时序数据，回退应用版本即可，不回退数据。
