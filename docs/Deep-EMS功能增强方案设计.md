# Deep-EMS功能增强方案设计

**文档版本**: V1.0  
**创建日期**: 2026-03-26  
**适用项目**: 钢厂智慧能碳管理平台  
**基础平台**: Deep-EMS（祝融能源管理系统）

---

## 一、方案概述

### 1.1 方案定位

本方案采用"Deep-EMS为主，逐步增强"的策略，以Deep-EMS（99.7%完成度）作为核心基础平台，借鉴MyEMS、cp-ems-ruoyi、Super-ERP-MES等平台的成熟模块设计，构建完整的钢厂智慧能碳管理平台。

### 1.2 方案优势

| 优势类别 | 说明 |
|---------|------|
| **风险低** | 基于Deep-EMS的99.7%完成度，核心模块已完善，基础稳固 |
| **见效快** | 核心模块已实现，可快速交付，缩短项目周期 |
| **成本低** | 充分利用现有代码，减少重复开发，降低开发成本 |
| **可扩展** | 模块化设计，便于后续功能扩展和系统升级 |
| **技术成熟** | Deep-EMS采用主流技术栈（Spring Boot + Vue.js），稳定性高 |

### 1.3 增强目标

1. **核心功能完善**：在Deep-EMS基础上，增强能源监控、能源分析、碳资产管理能力
2. **扩展功能补充**：补充新能源管理（光伏、储能、微电网）、生产管理、质量管理等模块
3. **高级功能开发**：开发调度优化、三维能源孪生工厂、系统集成等高级功能
4. **整体覆盖度提升**：从当前的82%提升至85%以上

## 三、方案设计

### 3.1 整体架构设计

#### 3.1.1 架构原则

1. **模块化设计**：各功能模块独立开发、独立部署，降低耦合度
2. **可扩展性**：采用插件化设计，便于后续功能扩展
3. **技术一致性**：保持Spring Boot + Vue.js技术栈，降低技术复杂度
4. **数据统一**：建立统一的数据标准和接口规范，实现数据共享
5. **安全可靠**：完善的权限控制、数据加密、日志审计机制

### 3.2 技术架构设计

#### 3.2.1 技术栈规划

**后端技术栈**
```
基础框架：Spring Boot 2.x
持久层：MyBatis Plus + Sa-Token
数据库：MySQL 8.0 + Redis 7.2 + TDengine 3.2.2
消息队列：RabbitMQ 3.12
物联网协议：MQTT（Spring Integration）
任务调度：XXL-Job 2.3.1
缓存：Redis（会话存储、数据缓存、分布式锁）
时序数据库：TDengine（能耗历史数据）
```

**前端技术栈**
```
前端框架：Vue 2.6.12
UI组件库：Element UI 2.15.12
数据可视化：ECharts 5.4.0
路由管理：Vue Router 3.4.9
状态管理：Vuex 3.6.0
HTTP客户端：Axios 0.24.0
```

**基础设施**
```
Web服务器：Nginx
容器化：Docker + docker-compose
监控：服务器监控、Redis监控
日志：操作日志、登录日志、系统日志
```

#### 3.2.3 接口设计

**统一API接口规范**
```
1. 接口地址规范
   GET    /api/v1/{module}/{resource}     查询列表
   GET    /api/v1/{module}/{resource}/{id} 查询详情
   POST   /api/v1/{module}/{resource}     新增
   PUT    /api/v1/{module}/{resource}/{id} 修改
   DELETE /api/v1/{module}/{resource}/{id} 删除

2. 响应格式规范
   {
     "code": 200,
     "message": "success",
     "data": {}
   }

3. 认证授权规范
   - Token认证：基于Sa-Token
   - 权限控制：基于角色和数据权限
   - 日志审计：记录所有API调用

4. 数据格式规范
   - 日期时间：ISO 8601格式
   - 数值精度：保留2位小数
   - 分页参数：pageNo、pageSize
```
