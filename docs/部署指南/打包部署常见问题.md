# 打包部署常见问题汇总

本文档汇总 Deep-EMS 项目在打包和部署过程中遇到的常见问题及解决方案。

---

## 一、Docker 镜像构建问题

### 1.1 Docker Build 缓存导致源码未更新

**问题描述**：

执行 `docker build` 时，Docker 默认会复用缓存层。当 `COPY . .` 那步命中缓存时，源码没有重新复制进去，使用的还是旧的 jar 包，导致修改的代码没有生效。

**错误现象**：

```
# 构建看似成功，但实际使用的是旧代码
docker build -t zhurong-ems-backend:4.6.0 -f zhurong-ems-admin/Dockerfile .
```

**解决方案**：

方案一：强制不使用缓存（完整重建）

```bash
docker build -t zhurong-ems-backend:4.6.0 -f zhurong-ems-admin/Dockerfile . --no-cache
```

方案二：仅让 Maven 那步跳过缓存（推荐，速度更快）

```bash
docker build -t zhurong-ems-backend:4.6.0 -f zhurong-ems-admin/Dockerfile . --build-arg CACHEBUST=$(date +%s)
```

方案三：修改 Dockerfile，确保每个关键步骤都是最新的

---

### 1.2 镜像构建失败

**问题描述**：

Maven 依赖下载失败或构建超时。

**解决方案**：

```bash
# 先在本地编译打包
cd zhurong-ems-system
mvn clean package -DskipTests

# 验证 jar 包是否存在
ls -la zhurong-ems-admin/target/*.jar

# 然后构建镜像
docker build -t zhurong-ems-backend:4.6.0 -f zhurong-ems-admin/Dockerfile .
```

## 二、容器启动问题

### 2.1 后端容器启动失败

**问题描述**：

容器启动后立即退出，或健康检查持续失败。

**排查步骤**：

```bash
# 1. 查看容器状态
docker ps -a | grep zhurong-ems

# 2. 查看容器日志
docker logs zhurong-ems-backend --tail 100

# 3. 检查依赖服务是否就绪
docker ps | grep -E "rabbitmq|emqx|tdengine|mysql|redis"
```

**常见原因及解决方案**：

#### 原因1：健康检查超时

容器启动较慢，健康检查间隔太短。

```yaml
# 修改 docker-compose.yml 中的健康检查配置
healthcheck:
  test: ["CMD-SHELL", "curl -f http://localhost:8088/autoee-iot-ems/actuator/health || exit 1"]
  interval: 30s      # 增加检查间隔
  timeout: 10s       # 增加超时时间
  retries: 3        # 增加重试次数
  start_period: 120s  # 增加启动等待时间
```

#### 原因2：依赖服务未就绪

RabbitMQ、EMQ X 等依赖服务未启动完成。

```bash
# 手动启动依赖服务
docker compose -f docker-compose-54.yml up -d zhurong-ems-rabbitmq zhurong-ems-emqx

# 等待依赖服务就绪后再启动后端
sleep 30
docker compose -f docker-compose-54.yml up -d zhurong-ems-backend
```

#### 原因3：配置错误

环境变量配置有误。

```bash
# 进入容器检查配置
docker exec -it zhurong-ems-backend env | grep -E "SPRING|MQTT|RABBITMQ"
```

---

### 2.2 健康检查持续失败

**问题描述**：

后端服务日志显示已启动成功，但健康检查持续返回失败。

**排查步骤**：

```bash
# 1. 确认服务是否正常启动
docker logs zhurong-ems-backend | grep "Started cpEmsApplication"

# 2. 在容器内手动测试健康检查端点
docker exec -it zhurong-ems-backend curl http://localhost:8088/autoee-iot-ems/actuator/health

# 3. 检查端口映射
docker port zhurong-ems-backend
```

**解决方案**：

如果服务已启动但健康检查失败，可能是容器内 curl 命令不可用。修改健康检查方式：

```yaml
healthcheck:
  test: ["CMD-SHELL", "wget -q --spider http://localhost:8088/autoee-iot-ems/actuator/health || exit 1"]
  # 或使用 docker exec
  # test: ["CMD", "docker", "exec", "zhurong-ems-backend", "curl", "-f", "http://localhost:8088/autoee-iot-ems/actuator/health"]
```

---

### 2.3 "Ambiguous mapping" 错误

**问题描述**：

Spring MVC 控制器存在映射冲突。

**错误日志**：

```
Ambiguous mapping. Cannot map 'xxxController' method
```

**解决方案**：

检查控制器方法是否有重复的 `@RequestMapping` 路径，或使用 `@GetMapping`、`@PostMapping` 等更精确的注解。

## 三、网络问题

### 3.1 legal-network 网络不存在

**问题描述**：

启动容器时报错：network `legal-network` not found。

**错误信息**：

```
ERROR: Network xxxx not found
```

**解决方案**：

方案一：创建外部网络

```bash
# 创建网络（如果不存在）
docker network create legal-network

# 或在 docker-compose.yml 中声明为 external
networks:
  legal-network:
    external: true
    name: legal-network
```

方案二：使用 bridge 网络

```yaml
networks:
  default:
    driver: bridge
```

---

### 3.2 容器间无法通信

**问题描述**：

容器之间无法通过服务名访问。

**排查步骤**：

```bash
# 1. 检查容器是否在同一网络
docker network inspect legal-network | grep -A 5 "Containers"

# 2. 测试网络连通性
docker exec zhurong-ems-backend ping -c 3 zhurong-ems-rabbitmq

# 3. 检查 DNS 解析
docker exec zhurong-ems-backend nslookup zhurong-ems-emqx
```

**解决方案**：

确保所有容器都连接到同一个网络：

```yaml
services:
  zhurong-ems-backend:
    networks:
      - legal-network
  zhurong-ems-rabbitmq:
    networks:
      - legal-network
```

## 四、数据库连接问题

### 4.1 MySQL 连接失败

**问题描述**：

后端无法连接 MySQL 数据库。

**排查步骤**：

```bash
# 1. 检查 MySQL 容器状态
docker ps | grep mysql

# 2. 测试 MySQL 连接
docker exec -it zhurong-ems-backend mysql -h legal-mysql -P 3306 -u root -p

# 3. 检查数据库是否存在
docker exec -it legal-mysql mysql -u root -p -e "SHOW DATABASES;"
```

**配置项对照表**：

| 配置项 | 旧值 | 新值 |
|--------|------|------|
| MySQL 地址 | localhost:3306 | legal-mysql:3306 |
| 数据库名 | autoee-iot-ems-app-20080 | autoee_ems |
| SSL 配置 | useSSL=true | useSSL=false |
| 时区 | UTC | Asia/Shanghai |

**常见错误及解决**：

#### 错误1：Access denied

用户名或密码错误，检查环境变量配置。

```yaml
SPRING_DATASOURCE_DYNAMIC_DATASOURCE_MASTER_USERNAME: root
SPRING_DATASOURCE_DYNAMIC_DATASOURCE_MASTER_PASSWORD: root
```

#### 错误2：Unknown database

数据库不存在，需要创建数据库。

```sql
CREATE DATABASE autoee_ems CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

#### 错误3：SSL 相关错误

添加 `useSSL=false` 和 `allowPublicKeyRetrieval=true` 参数。

```
jdbc:mysql://legal-mysql:3306/autoee_ems?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
```

## 五、MQTT/EMQ X 问题

### 5.1 EMQ X 连接失败

**问题描述**：

后端无法连接到 EMQ X MQTT Broker。

**排查步骤**：

```bash
# 1. 检查 EMQ X 容器状态
docker ps | grep emqx

# 2. 查看 EMQ X 日志
docker logs zhurong-ems-emqx --tail 50

# 3. 测试 MQTT 端口
docker exec -it zhurong-ems-backend nc -zv zhurong-ems-emqx 1883

# 4. 测试 Dashboard API
curl http://localhost:18083/api/v5/health/check
```

**EMQ X 5.x 配置变化**：

EMQ X 5.x 版本的配置格式有较大变化，常见配置对照：

| 配置项 | EMQ X 4.x | EMQ X 5.x |
|--------|-----------|-----------|
| Dashboard 用户名 | EMQX_DASHBOARD__DEFAULT_USERNAME | EMQX_Dashboard__default_username |
| Dashboard 密码 | EMQX_DASHBOARD__DEFAULT_PASSWORD | EMQX_Dashboard__default_password |
| 健康检查 | emqx ctl status | /opt/emqx/bin/emqx_ctl status |
| 端口 | 8081（无） | 8081（WebSocket） |

**EMQ X 5.x 常用环境变量**：

```yaml
environment:
  TZ: Asia/Shanghai
  EMQX_NAME: emqx
  EMQX_HOST: 127.0.0.1
  EMQX_Dashboard__default_username: admin
  EMQX_Dashboard__default_password: public
  EMQX MQTT__DEFAULT__LISTENER: 1883
  EMQX MQTT__DEFAULT__MAX_PACKET_SIZE: 1MB
  EMQX MQTT__DEFAULT__MAX_CLIENTID_LEN: 128
  EMQX MQTT__DEFAULT__MAX_KEEPALIVE: 360
  EMQX MQTT__DEFAULT__KEEPALIVE_BACKOFF: 0.75
```

**MQTT 配置项对照表**：

| 配置项 | 旧值 | 新值 |
|--------|------|------|
| MQTT 地址 | localhost:1883 | tcp://zhurong-ems-emqx:1883 |
| 用户名 | 无 | admin |
| 密码 | 无 | public |
| Client ID | 固定值 | 动态生成避免重复 |
| Keepalive | 60 | 360 |

---

### 5.2 EMQ X 健康检查失败

**问题描述**：

EMQ X 5.x 容器健康检查持续失败。

**解决方案**：

```yaml
healthcheck:
  # EMQ X 5.x 使用 emqx_ctl 而非 emqx
  test: ["CMD", "/opt/emqx/bin/emqx_ctl", "status"]
  interval: 10s
  timeout: 5s
  retries: 5
```

## 八、容器重启相关问题

### 8.1 容器无法停止

**问题描述**：

执行 `docker compose down` 时容器无法正常停止。

**解决方案**：

```bash
# 强制停止并删除容器
docker compose -f docker-compose-54.yml rm -s -f zhurong-ems-backend

# 或分步执行
docker stop zhurong-ems-backend
docker rm -f zhurong-ems-backend
```

---

### 8.2 数据卷权限问题

**问题描述**：

容器无法写入数据卷。

**解决方案**：

```bash
# 检查数据卷权限
docker volume inspect zhurong-ems-backend-logs

# 修改数据卷权限
docker run --rm -v zhurong-ems-backend-logs:/data alpine chmod 777 /data

# 或使用 named volumes（推荐）
volumes:
  - zhurong-ems-backend-logs:/zhurong-ems/server/logs
```

## 十一、常见错误代码对照

| 错误代码/关键词 | 可能原因 | 解决方案 |
|----------------|----------|----------|
| `Ambiguous mapping` | 控制器方法映射冲突 | 检查控制器注解 |
| `Connection refused` | 服务未启动或端口错误 | 检查服务状态和端口 |
| `Access denied` | 用户名或密码错误 | 检查环境变量配置 |
| `Unknown database` | 数据库不存在 | 创建数据库 |
| `Network not found` | 网络未创建 | 创建网络或修改配置 |
| `No such container` | 容器不存在 | 检查容器名称 |
| `OCI runtime` | 容器启动失败 | 查看日志排查原因 |
| `Health check timeout` | 健康检查超时 | 增加超时时间和重试次数 |
