## 国际化开发

### 1. 语言包结构

所有语言包位于 `src/i18n/lang/` 目录，包含四种语言：

- `zh-CN.js` - 中文
- `en.js` - 英文
- `id.js` - 印尼语
- `ru.js` - 俄语

### 2. 添加新的国际化条目

**步骤 1：在中文语言包中添加**

```javascript
// src/i18n/lang/zh-CN.js
export default {
  menu: {
    // 新增模块
    patrol: {
      title: '巡更管理',
      point: '巡更点位',
      route: '巡更路线',
      plan: '巡更计划',
      record: '巡更记录',
      alarm: '巡更报警',
      task: '巡更任务'
    }
  }
}
```

**步骤 2：在其他语言包中翻译**

```javascript
// src/i18n/lang/en.js
export default {
  menu: {
    patrol: {
      title: 'Patrol Management',
      point: 'Patrol Points',
      route: 'Patrol Routes',
      plan: 'Patrol Plans',
      record: 'Patrol Records',
      alarm: 'Patrol Alarms',
      task: 'Patrol Tasks'
    }
  }
}
```

### 3. 动态菜单国际化映射

对于后端返回的中文菜单名，需要在 `src/i18n/helper.js` 中添加映射：

```javascript
export const menuTitleMap = {
  // 巡更管理
  '巡更管理': 'menu.patrol.title',
  '巡更点位': 'menu.patrol.point',
  '巡更路线': 'menu.patrol.route',
  '巡更计划': 'menu.patrol.plan',
  '巡更记录': 'menu.patrol.record',
  '巡更报警': 'menu.patrol.alarm',
  '巡更任务': 'menu.patrol.task'
}
```

### 4. 更新 possibleKeys 数组

在 `src/i18n/helper.js` 的 `translateMenuTitle` 函数中：

```javascript
const possibleKeys = [
  `menu.${title}`,
  `menu.patrol.${title}`,
  `menu.itemManage.${title}`,
  `menu.chargingOperation.${title}`,
  `menu.pvManage.${title}`,
  `menu.alarmManage.${title}`,
  `menu.energyStatus.${title}`,
  `menu.usageMonitor.${title}`
]
```

### 5. 在组件中使用

```vue
<template>
  <div>
    <!-- 方式 1：使用 $t -->
    <h1>{{ $t('menu.patrol.title') }}</h1>
    
    <!-- 方式 2：使用 t() 函数 -->
    <span>{{ t('menu.patrol.point') }}</span>
  </div>
</template>

<script>
import { useI18n } from 'vue-i18n'

export default {
  setup() {
    const { t } = useI18n()
    return { t }
  }
}
</script>
```

### 6. 默认语言配置

修改 `src/i18n/index.js` 设置默认语言为英文：

```javascript
// 获取默认语言
export function getDefaultLang() {
  const cookieLang = Cookies.get('language')
  const supportedLangCodes = supportLanguages.map(lang => lang.code)
  
  if (cookieLang && supportedLangCodes.includes(cookieLang)) {
    return cookieLang
  }

  // 根据浏览器语言自动检测
  const browserLang = navigator.language || navigator.browserLanguage
  if (browserLang) {
    if (browserLang.startsWith('zh')) return 'zh-CN'
    if (browserLang.startsWith('en')) return 'en'
    if (browserLang.startsWith('id')) return 'id'
    if (browserLang.startsWith('ru')) return 'ru'
  }

  // 默认返回英文
  return 'en'
}
```

## Docker 容器化部署

### 1. Dockerfile 配置

项目使用多阶段构建优化镜像大小：

```dockerfile
# =============================================
# 阶段 1：构建阶段
# =============================================
FROM node:20-bookworm-slim AS build

WORKDIR /build

# 复制 package 文件
COPY package*.json ./

# 配置国内镜像源
RUN npm config set registry https://registry.npmmirror.com

# 安装依赖
RUN npm install

# 复制源代码
COPY . .

# 构建项目
ARG VUE_APP_BASE_API=/prod-api
RUN NODE_OPTIONS=--openssl-legacy-provider npm run build

# =============================================
# 阶段 2：运行阶段
# =============================================
FROM nginx:1.28.3-alpine

# 复制构建产物
COPY --from=build /build/dist /usr/share/nginx/html

# 复制 Nginx 配置
COPY nginx.conf /etc/nginx/conf.d/default.conf

# 创建日志目录
RUN mkdir -p /var/log/nginx

EXPOSE 80

CMD ["nginx", "-g", "daemon off;"]
```

### 2. 构建镜像

```bash
# 方式 1：直接构建
docker build -t zhurong-ems/frontend:latest \
  --build-arg VUE_APP_BASE_API=/prod-api \
  .

# 方式 2：使用 docker-compose
docker-compose -f docker-compose.full.yml build zhurong-ems-frontend
```

### 3. 运行容器

```bash
# 停止并删除旧容器
docker stop zhurong-ems-frontend
docker rm zhurong-ems-frontend

# 启动新容器
docker run -d \
  --name zhurong-ems-frontend \
  --network zhurong-ems-network \
  -p 3080:80 \
  --restart unless-stopped \
  zhurong-ems/frontend:latest
```

### 4. 使用 Docker Compose 部署

在 `docker-compose.full.yml` 中配置：

```yaml
zhurong-ems-frontend:
  image: zhurong-ems/frontend:latest
  container_name: zhurong-ems-frontend
  restart: unless-stopped
  ports:
    - "3080:80"
  environment:
    - VUE_APP_BASE_API=/prod-api
  depends_on:
    - zhurong-ems-backend
  networks:
    - zhurong-ems-network
  healthcheck:
    test: ["CMD", "wget", "-q", "--spider", "http://localhost:80"]
    interval: 30s
    timeout: 10s
    retries: 3
```

启动服务：

```bash
docker-compose -f docker-compose.full.yml up -d zhurong-ems-frontend
```

## 网络配置

### 1. Nginx 配置

关键配置项：API 代理和静态资源缓存

```nginx
server {
    listen 80;
    server_name localhost;
    root /usr/share/nginx/html;
    index index.html;

    # Gzip 压缩
    gzip on;
    gzip_types text/plain text/css application/json application/javascript;
    gzip_min_length 1000;

    # API 代理配置（优先匹配）
    location /prod-api/ {
        proxy_pass http://zhurong-ems-backend:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_connect_timeout 60s;
        proxy_read_timeout 60s;
    }

    # 静态资源缓存
    location ~* \.(jpg|jpeg|png|gif|ico|css|js|svg|woff|woff2|ttf|eot)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # SPA 路由支持
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 错误页面
    error_page 404 /404.html;
    error_page 500 502 503 504 /50x.html;
}
```

### 2. Docker 网络

确保前端和后端在同一网络：

```bash
# 创建网络
docker network create zhurong-ems-network

# 查看网络
docker network inspect zhurong-ems-network

# 将容器加入网络
docker network connect zhurong-ems-network zhurong-ems-frontend
docker network connect zhurong-ems-network zhurong-ems-backend
```

### 3. 环境变量传递

前端通过 Nginx 环境变量传递配置：

```bash
# 在 docker-compose.yml 中
environment:
  - VUE_APP_BASE_API=/prod-api
```

## 常见问题与解决方案

### 1. 502 Bad Gateway

**问题现象**：访问前端页面显示 502 错误

**原因**：Nginx 无法连接到后端服务

**解决方案**：
1. 检查后端容器是否运行：`docker ps | grep backend`
2. 检查网络配置：确保前后端在同一网络
3. 检查 Nginx 配置：确认 `proxy_pass` 地址正确
4. 测试网络连通性：`docker exec zhurong-ems-frontend ping zhurong-ems-backend`

```bash
# 诊断步骤
docker logs zhurong-ems-frontend  # 查看前端日志
docker logs zhurong-ems-backend   # 查看后端日志
docker network inspect zhurong-ems-network  # 检查网络
```

### 2. 系统内部错误

**问题现象**：页面加载后显示"系统内部错误"

**原因**：API 请求返回错误，可能是后端服务异常

**解决方案**：
1. 查看后端日志定位具体错误
2. 检查数据库连接
3. 检查 Redis 连接
4. 验证 API 路由配置

### 3. 菜单未国际化

**问题现象**：切换语言后，部分菜单仍显示中文

**原因**：
1. 语言包中缺少对应翻译
2. helper.js 中缺少中文到 key 的映射
3. possibleKeys 数组未包含新模块

**解决方案**：
1. 在 4 个语言包中添加翻译
2. 在 `menuTitleMap` 中添加映射
3. 在 `possibleKeys` 中添加模块路径
4. 重新构建并部署

### 4. 默认语言不是英文

**问题现象**：首次登录显示中文，而非英文

**原因**：`getDefaultLang()` 函数默认返回'zh-CN'

**解决方案**：
修改 `src/i18n/index.js`：

```javascript
// 默认返回英文
return 'en'
```

### 5. 语言切换不生效

**问题现象**：切换语言后，部分页面未更新

**原因**：
1. 组件未响应 `$i18n.locale` 变化
2. 使用了硬编码文本
3. 缓存问题

**解决方案**：
1. 使用响应式的 `t()` 函数
2. 所有文本使用 `$t()` 翻译
3. 清除浏览器缓存
4. 在关键组件中添加 `watch` 监听

### 6. 构建失败 - OpenSSL 错误

**问题现象**：`npm run build` 报错 OpenSSL 相关错误

**解决方案**：
```bash
# 使用 OpenSSL 遗留支持
set NODE_OPTIONS=--openssl-legacy-provider && npm run build
```

或在 `package.json` 中修改脚本：

```json
{
  "scripts": {
    "build": "set NODE_OPTIONS=--openssl-legacy-provider && vue-cli-service build"
  }
}
```

### 7. 容器启动失败

**问题现象**：容器创建后立即退出

**原因**：
1. Nginx 配置错误
2. 端口冲突
3. 缺少必要文件

**解决方案**：
```bash
# 查看容器日志
docker logs zhurong-ems-frontend

# 检查配置文件
docker exec -it zhurong-ems-frontend cat /etc/nginx/conf.d/default.conf

# 重新构建镜像
docker build --no-cache -t zhurong-ems/frontend:latest .
```

### 8. 静态资源加载失败

**问题现象**：页面空白，控制台报 404 错误

**原因**：
1. `publicPath` 配置错误
2. 资源路径不正确

**解决方案**：
在 `vue.config.js` 中配置：

```javascript
module.exports = {
  publicPath: process.env.NODE_ENV === 'production' ? '/' : '/'
}
```

本文档总结了 Deep-EMS 项目前端开发到部署的完整流程，关键点：

1. **国际化开发**：所有用户可见文本使用 `$t()`，维护完整的语言包和映射表
2. **多阶段构建**：使用 Docker 多阶段构建优化镜像大小
3. **网络配置**：确保前后端在同一 Docker 网络，Nginx 正确配置 API 代理
4. **健康检查**：配置容器健康检查确保服务可用
5. **日志监控**：及时查看容器日志定位问题
6. **版本管理**：使用语义化版本管理镜像，便于回滚

遵循这些最佳实践，可以确保前端应用的开发效率和部署稳定性。
