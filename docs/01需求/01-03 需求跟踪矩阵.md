## 1. 编制说明

1. 本矩阵是 V4.6.0 需求全生命周期追溯的唯一受控清单，覆盖《软件需求规格说明书（SRS）V1.0》中各业务域关键功能需求（FR）、医院模块 FR-HOSP-01~20 及关键非功能/合规需求（NFR/CMP）。
2. 追溯链路为：**需求来源 → 需求编号 → 设计文档 → 开发任务 → 测试用例 → 验收标准 → 当前状态**，任一环节缺失即视为覆盖不完整。
3. 本矩阵与 SRS、测试用例库、开发任务看板保持同步；基线后变更必须登记于第 5 章。
4. 主表共 **68 行**：医院新增需求 20 行（FR-HOSP-01~20），既有业务域基线需求 41 行，非功能与合规需求 7 行。

## 2. 图例与取值规范

### 2.1 优先级

| 取值 | 含义 |
| --- | --- |
| P0 | 必须（Must），不实现则不可验收 |
| P1 | 应该（Should），本版本应交付，顺延须书面批准 |
| P2 | 可以（Could），资源允许时交付 |

### 2.2 需求状态

| 状态 | 含义 |
| --- | --- |
| 已基线 | 已纳入需求基线；既有能力已上线，本版本保持行为不变（以回归测试覆盖） |
| 开发中 | 新增需求，正在开发 |
| 待联调 | 开发完成，等待与外部 IOT 平台/中间件联调 |
| 待开发 | 已基线，尚未开始开发 |
| 待测试 | 开发与联调完成，等待/正在测试 |
| 已验收 | 测试通过且验收标准达成 |
| 已变更 | 基线后发生变更，见第 5 章 |
| 已搁置 | 经审批暂缓，不进入本版本 |

### 2.3 需求来源编号

- SRC-xx：调研报告附录登记的原始需求来源（见 01-01 第 6.2 节）；
- P-xx：调研报告痛点编号；
- 基线：V4.6.0 既有能力（源自 docs/系统功能清单.md、docs/Deep-EMS产品设计文档.md）；
- 政策：双碳/节能监察/等保/GDPR 等合规要求。

### 2.4 编号规则

- 需求：FR-域-序号 / NFR-类别-序号 / CMP-序号（与 SRS 一致）；
- 开发任务：TASK-域-序号；测试用例：TC-域-序号（在用例库中可展开多条用例）。
