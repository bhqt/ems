# 1. 引言

## 1.1 目的

本说明书旨在明确 V4.6.0 的功能与非功能需求，为概要设计、详细设计、开发、测试、验收及项目管理提供统一、可验证、可追溯的依据。本文档特别定义在既有企业级能源管理平台之上以**加性开发**方式新增的"医院智慧能源决策系统"需求，该新增能力通过外部 IOT 平台 HTTP 回调获取 CT、MRI、DR、超声、检验流水线、DSA 等检查检验设备数据，**既有系统全部功能保留且行为不被改写**。

## 1.2 范围

**本版本包含**：

- 基线能力：设备管理、能耗分析、报警管理、运维管理、物品管理、定额管理、充电桩管理、碳资产、视频监控、数据查询、管理体系、计量管理、新能源、水务、调度、数字孪生、集控、报表引擎、系统集成与数据同步、系统管理、系统监控等业务域；
- 新增能力：医院智慧能源决策系统（回调接入层、设备台账、指标体系、院区分区、实时监测、工作量与能效评估、分区能耗、节能建议、医院报警、医院大屏、多院区隔离、国际化）；
- 支撑能力：MQTT 直采、HTTP 回调、OSS、短信、视频平台、第三方系统集成等外部接口，以及性能、安全、可用性、国际化等非功能需求。

**本版本不包含**：外部 IOT 平台自身改造、HIS/PACS/LIS/RIS 诊疗流程改造、硬件施工，以及 Vue3 演进版与 uni-app 移动端的医院功能强制交付（仅保留接口兼容预期）。

# 2. 产品概述

## 2.1 产品定位

是一套面向园区、企业及公共机构（含医院）的企业级智慧能源管理平台。V4.6.0 在通用能源管理能力之上，面向医院场景新增"智慧能源决策系统"：以外部 IOT 平台回调数据为输入，实现检查检验设备级的"采集接入—标准化—高可靠存储—实时监测—报警联动—能效评估—节能决策"闭环，并支持多院区隔离与中英等多语言，满足国内合规与海外推广双重要求。

## 2.2 产品全景

平台采用分层结构：

1. **接入层**：MQTT 直采（EMQX 5.3.2，面向通用计量/传感设备）、HTTP 回调接入（面向 IOT 平台与医院设备）、系统集成数据同步接口；
2. **消息与存储层**：RabbitMQ 3.12 异步削峰；MySQL 8.0（库 `autoee_ems`）存档案/配置/业务数据，TDengine 3.x 存时序数据（可开关，关闭时降级写 MySQL 时序表）；Redis 7.2 缓存与分布式协同；XXL-Job 定时调度；
3. **业务层**：既有 20 余个业务域 + 医院模块（独立包、独立菜单、独立表前缀，加性叠加）；
4. **应用层**：Vue 2.6 + Element UI + ECharts Web 端（dev 端口 9029），大屏与看板；规划 Vue3 演进版与 uni-app 移动端；
5. **治理层**：Sa-Token + JWT 认证、菜单/数据/按钮三类权限、审计日志、国际化（中/英/俄/印尼）、系统监控。

服务端：Spring Boot 2.7.9，JDK 1.8（强制），端口 8088，context-path `/autoee-iot-ems`。

## 2.5 约束与假设

- **C1 加性开发**：医院模块不得修改既有业务域的表结构语义、接口契约与页面行为；复用能力以调用/继承方式使用；
- **C2 技术栈锁定**：JDK 1.8、Spring Boot 2.7.9 与既定中间件版本，不允许引入要求 JDK 11+ 的依赖；
- **C3 TDengine 可开关**：`td.enabled=false` 时医院回调链路必须仍可完整运行（时序数据降级落 MySQL）；
- **C4 数据来源**：检查检验设备数据只来自外部 IOT 平台回调，平台不直连医疗设备；
- **C5 安全红线**：默认管理员账号 admin/123456 仅限初始环境，投产必须改密；全链路 HTTPS；
- 假设：IOT 平台提供稳定测试环境、报文样例与鉴权配合；医院提供台账与工作量口径数据。

# 3. 功能需求

## 3.1 编号与说明规则

- 编号格式：`FR-<域>-<序号>`，域编码见各节；医院模块序号为 FR-HOSP-01~20；
- 每条需求给出：优先级、参与者、前置条件、输入、处理规则、输出、异常处理；
- 优先级 P0（必须）/P1（应该）/P2（可以）定义见附录 A；
- 标注"基线"的需求表示 V4.6.0 既有能力，本版本保持行为不变，仅声明范围；标注"新增"的为医院加性能力。

### 3.2 设备管理（FR-EQP，基线）

**FR-EQP-01　设备档案管理**　【P0｜基线】
- 参与者：设备管理员（增改删）、授权用户（查询）
- 前置条件：已登录，具备设备管理菜单与对应按钮权限
- 输入：设备编号、名称、类型、品牌型号、所属组织/分区、位置、投运日期、额定参数、状态、附件
- 处理规则：设备编号全局唯一；主键雪花算法（ASSIGN_ID）；逻辑删除 `del_flag`（0 存在/2 删除）；支持条件分页、导入导出；设备可绑定网关与测点
- 输出：档案列表/详情、导入结果、操作结果提示
- 异常处理：编号重复拦截；必填/格式校验返回字段级错误；删除已被测点或台账引用的设备时阻止并给出引用位置

**FR-EQP-02　网关管理**　【P1｜基线】
- 参与者：设备管理员、IOT 运维
- 前置条件：网关档案已建立
- 输入：网关编号、型号、通讯协议、上线状态、心跳周期、绑定设备
- 处理规则：维护网关与设备归属；心跳超时标记离线；网关状态变更写日志
- 输出：网关列表、在线/离线状态、拓扑视图
- 异常处理：网关心跳丢失按周期置离线并告警；重复注册提示冲突

### 3.3 能耗分析（FR-ENE，基线）

**FR-ENE-01　能耗概况**　【P0｜基线】
- 参与者：能源管理负责人、决策层
- 前置条件：存在计量数据与组织/分项维度
- 输入：时间范围、组织/院区、能源种类
- 处理规则：汇总总能耗、各能源种类占比、关键指标卡片；支持按权限过滤
- 输出：概况看板（指标卡、饼图、柱图）
- 异常处理：无数据时显式空状态并提示数据范围，不以 0 误导

**FR-ENE-02　能耗趋势与同环比**　【P0｜基线】
- 参与者：能源管理负责人
- 输入：时间粒度（时/日/月/年）、维度、对比周期
- 处理规则：按粒度聚合，计算同比、环比与差异率；口径可配置
- 输出：趋势曲线、同环比对比表
- 异常处理：对比期缺数时标记"缺数"，不参与百分比计算

**FR-ENE-03　分项、流向与损耗分析**　【P1｜基线】
- 输入：分项模型（照明/空调/动力/特殊等）、拓扑节点
- 处理规则：按分项归集；按能源流向逐级计算输配损耗率
- 输出：桑基/流向图、分项占比、损耗率排行
- 异常处理：拓扑不完整时给出缺失环节提示

**FR-ENE-04　费用、能源平衡与标杆**　【P1｜基线】
- 处理规则：按价格方案计算费用；基于总表与分表之和做能源平衡校验；支持标杆值/定额对标
- 输出：费用报表、平衡偏差表、标杆对比图
- 异常处理：平衡偏差超阈值标记异常并可转报警核查

**FR-ENE-05　电能质量**　【P2｜基线】
- 输入：电压、电流、功率因数、谐波、三相不平衡等电参量
- 处理规则：越限统计与越限时长累计；事件化留存
- 输出：电能质量曲线与越限事件表
- 异常处理：测点缺失时降级展示可用项

### 3.4 报警管理（FR-ALM，基线）

**FR-ALM-01　实时报警与历史查询**　【P0｜基线】
- 参与者：值班人员、设备科/后勤
- 前置条件：报警规则已配置且数据接入正常
- 输入：实时数据点、报警等级/状态/时间范围等查询条件
- 处理规则：实时计算触发/恢复；按等级声光提示；历史支持多维检索、确认、批注
- 输出：实时报警栏、历史列表、报警明细
- 异常处理：服务重启后未恢复报警状态可重建；重复报警按防抖/延时配置合并

**FR-ALM-02　报警规则配置**　【P0｜基线】
- 输入：测点、规则类型（上下限/突变/无数据/组合逻辑）、阈值、等级、时段、防抖
- 处理规则：规则启用/停用版本化；支持分级与生效时段
- 输出：规则列表、模拟校验结果
- 异常处理：规则表达式非法在保存时拦截；测点失效规则自动标记异常

**FR-ALM-03　报警联动**　【P1｜基线】
- 处理规则：报警触发后按配置联动发送邮件、生成维修工单；联动动作留痕
- 输出：联动记录、工单入口
- 异常处理：邮件/工单失败自动重试并记录失败原因，不影响报警主流程

### 3.5 运维管理（FR-OMS，基线）

**FR-OMS-01　巡检计划与任务**　【P1｜基线】
- 参与者：能源管理负责人、班组长、巡检人员
- 输入：巡检周期、点位、路径、责任人、班次
- 处理规则：按计划由 XXL-Job 生成巡检任务；超时未执行提醒；漏检统计
- 输出：计划、任务、路径、漏检报表
- 异常处理：节假日排班冲突按配置调期并通知

**FR-OMS-02　巡检记录与巡检点**　【P1｜基线】
- 输入：巡检点定义（位置、检查项、正常值域）、现场记录值与图片
- 处理规则：逐项填报，异常项可一键转报警/工单；记录不可篡改、可补录审批
- 输出：巡检记录单、异常清单
- 异常处理：值越出域自动标异常并要求处置说明

**FR-OMS-03　维修工单**　【P0｜基线】

### 3.21 医院智慧能源决策系统（FR-HOSP，新增）

> 本节 20 条需求为 V4.6.0 新增核心范围，全部以加性方式实现，复用平台权限、字典、消息、审计与国际化框架。

#### FR-HOSP-01　IOT HTTP 回调接收　【P0｜新增】
- 参与者：外部 IOT 平台（数据发送方）、IOT 运维
- 前置条件：院区与接入配置已建立；回调地址已告知 IOT 平台；HTTPS 证书有效
- 输入：IOT 平台 POST 的 JSON 报文（单条或批量数据点），含设备标识、指标、值、时间戳、质量戳及厂商扩展字段
- 处理规则：
  1. 提供独立回调端点，路径挂在 `/autoee-iot-ems` 之下，医院模块独立路由；
  2. 接入层无状态、可水平扩展，支持批量报文与 Keep-Alive；
  3. 接收后先做基础校验（必填、大小上限、JSON 合法性），校验通过即投递消息队列并快速 ACK，目标吞吐 ≥1000 TPS；
  4. 采用异步处理，HTTP 工作线程不执行落库等重操作；
  5. 对同一数据点（设备标识+指标+时间戳）幂等，重复投递不产生重复数据；
  6. 全量接收结果可在回调日志中查询（FR-HOSP-06）。
- 输出：标准化应答（接收编号/结果码/时间），HTTP 2xx 表示已受理；4xx 表示请求非法；5xx 表示平台暂不可用
- 异常处理：报文超大/非法返回 4xx 并记录原因；队列不可用返回 5xx 由 IOT 平台重试；突发流量由队列削峰

#### FR-HOSP-02　回调安全鉴权（Token/IP 白名单/签名）　【P0｜新增】
- 参与者：IOT 平台、IOT 运维、系统管理员
- 前置条件：已为每个院区/IOT 数据源分配凭证
- 输入：请求头中的 Token、签名、时间戳/随机数，来源 IP，原始报文体
- 处理规则：
  1. 支持 Token、IP 白名单、签名三种校验方式，均可按院区独立配置与启停；
  2. Token 支持有效期与轮换，凭证加密存储；签名校验覆盖报文与时间戳，防篡改防重放（时间戳容差可配置，默认 ±5 分钟）；
  3. 鉴权失败一律拒绝并记录安全日志（来源、原因、摘要，不记录敏感全文）；
  4. 连续失败达到阈值触发安全告警；
  5. 鉴权配置变更进入审计日志。
- 输出：鉴权通过/拒绝结果；安全审计记录
- 异常处理：鉴权服务异常时默认拒绝（fail-close）；白名单配置错误导致的拒绝可在审计中定位

#### FR-HOSP-03　报文解析与标准化（StandardDataPoint）　【P0｜新增】
- 参与者：系统管理员（配置映射）、系统
- 前置条件：设备台账与指标定义已存在
- 输入：厂商原始报文、字段映射规则、时区与单位换算配置
- 处理规则：
  1. 将厂商报文解析为统一标准数据点 StandardDataPoint：设备标识、指标编码、值、时间戳、质量戳（结构见附录 B）；
  2. 设备标识与指标编码按映射表转换；时间戳统一归一为带时区的标准时间并落 UTC；值按单位换算规则归一；
  3. 质量戳字典映射为 GOOD/UNCERTAIN/BAD/MISSING；非 GOOD 数据原始保留但默认不进入统计聚合；
  4. 无法识别的设备/指标进入"未映射数据"隔离区，不影响其他数据处理，并支持后续补映射后重放；
  5. 解析规则版本化，变更可追溯。
- 输出：标准数据点消息；未映射隔离清单；解析失败明细
- 异常处理：单条解析失败不影响同批次其他数据点；批量报文部分失败时返回分项计数

#### FR-HOSP-04　异步落库（MySQL + TDengine）　【P0｜新增】
- 参与者：系统
- 前置条件：消息队列可用；数据源与存储配置就绪
- 输入：队列中的 StandardDataPoint
- 处理规则：
  1. 消费 RabbitMQ 消息，原始报文归档，标准数据写 MySQL（最新值/业务关联）与 TDengine（历史时序）；
  2. TDengine 开关开启时双写；`td.enabled=false` 时自动降级写 MySQL 时序表，链路功能不缺失；
  3. 消费端按院区/批量提交，控制批次大小与并发，保证落库顺序在同设备指标内基本有序；
  4. 写入幂等（设备+指标+时间戳去重）；
  5. 最新值缓存至 Redis 供实时监测高频读取。
- 输出：可查询的历史时序数据、设备最新状态
- 异常处理：单批失败整体重试；存储故障时消息回到队列并触发积压告警，不 ACK 丢失

#### FR-HOSP-05　失败重试与可靠补偿（不丢数）　【P0｜新增】
- 参与者：系统、IOT 运维
- 前置条件：消息与死信机制可用
- 输入：处理失败的数据点消息
- 处理规则：
  1. 消费失败按指数退避重试（次数、间隔可配）；超过阈值转入死信队列；
  2. 死信数据保留原始报文与失败原因，支持运维在管理端查看、修复（如补映射、补配置）后一键重放；
  3. 提供回调接收与落库的对账能力（按时间窗/院区统计接收数、入库数、失败数）；
  4. 任何环节不得静默丢弃数据；IOT 平台重推同一数据点时幂等；
  5. RPO 目标：不丢数据（RPO=0 的业务承诺，至少做到可补偿重建）。
- 输出：重试记录、死信列表、重放结果、对账报表
- 异常处理：死信积压超阈值告警；重放失败保留状态并允许再次处理

#### FR-HOSP-06　回调日志　【P0｜新增】
- 参与者：IOT 运维、系统管理员
- 输入：每次回调请求与处理结果
- 处理规则：记录请求时间、来源 IP、院区/数据源、报文摘要与大小、鉴权结果、解析计数、落库计数、耗时、应答码、错误原因；原始报文按保留策略可查（受控权限、脱敏展示）；支持按院区/时间/结果检索与统计
- 输出：回调日志列表、详情、成功率/耗时统计
- 异常处理：日志写入失败不得影响主链路（异步落盘/降级），但须告警

#### FR-HOSP-07　检查检验设备台账　【P0｜新增】
- 参与者：设备科/后勤、系统管理员
- 前置条件：院区/分区已建立
- 输入：设备类别（CT/MRI/DR/超声/检验流水线/DSA）、设备编号、品牌型号、序列号、额定功率/参数、所属院区/分区/科室、位置、投运日期、厂商、维保信息、IOT 设备标识映射、状态
- 处理规则：
  1. 独立医院设备表（独立表前缀），与平台通用设备档案可建立关联但不修改其结构；
  2. 设备编号唯一、雪花主键、逻辑删除；支持批量导入导出；
  3. 一台设备绑定一个或多个 IOT 设备标识，绑定关系影响回调数据归属；
  4. 支持设备全生命周期状态（在用/停用/维修/报废）与变更留痕；
  5. 台账字段随多语言框架提供中英文标签。
- 输出：设备台账列表/详情、导入结果、设备—标识映射表
- 异常处理：导入冲突行明细返回；停用/报废设备的数据继续入库但不参与在役统计并单独标注

#### FR-HOSP-08　指标定义管理　【P0｜新增】
- 参与者：能源管理负责人、系统管理员

- 处理规则：指标统一定义、全院区共享；支持指标分组与厂商指标映射；工作量指标（如检查次数、扫描序列数）明确口径与单位；指标变更版本化，历史数据按当时口径留存
- 输出：指标目录、映射关系、口径说明
- 异常处理：停用指标不再参与新配置但历史可查；删除被引用指标被阻止

#### FR-HOSP-09　院区与分区管理　【P0｜新增】
- 参与者：系统管理员

- 输出：院区/分区树、配置详情
- 异常处理：删除下挂设备的院区/分区被阻止；时区变更影响新数据展示口径并给出确认提示

#### FR-HOSP-10　设备实时监测　【P0｜新增】

- 输出：实时监测总览、设备监测详情

#### FR-HOSP-12　设备能效评估　【P1｜新增】

# 4. 外部接口需求

## 4.1 接口总体要求

- 所有对外接口走 HTTPS；统一鉴权、限流、幂等与错误码规范；
- 接口契约版本化（URL/Header 携带版本），变更走变更控制；
- 敏感字段（凭证、密钥、个人信息）加密或脱敏，不在日志明文留存；
- 所有外部交互记录可追溯（调用方、时间、结果、耗时）。

## 4.2 接口清单

| 编号 | 接口 | 方向 | 协议/方式 | 关键内容 | 性能/可靠性要求 |
| --- | --- | --- | --- | --- | --- |
| EI-01 | MQTT 直采 | 设备/网关→平台 | MQTT over TLS（EMQX 5.3.2），主题订阅 | 通用计量与传感设备数据，平台订阅后经消息链路入库 | 支持主题级鉴权；断线经 MQTT QoS 与平台补偿保证不丢 |
| EI-02 | IOT HTTP 回调 | IOT 平台→平台 | HTTPS POST + JSON，Token/IP 白名单/签名 | 检查检验设备数据点批量推送（FR-HOSP-01~06） | ≥1000 TPS；异步 ACK；失败可重试、死信可重放 |
| EI-03 | 对象存储 OSS | 平台↔OSS | HTTPS API/SDK | 附件、报表、图片、模型文件；鉴权下载 | 上传下载失败重试；URL 有时效 |
| EI-04 | 短信 SMS | 平台→短信网关 | HTTPS API | 报警与通知短信 | 发送失败重试并留痕；频控防骚扰 |
| EI-05 | 邮件 | 平台→邮件服务 | SMTP/HTTPS | 报警联动、报表订阅 | 失败重试；模板化 |
| EI-06 | 视频平台 | 平台↔视频平台 | 厂商开放接口（按视频接入方案） | 通道树、预览/回放取流、报警联动 | 取流异常不阻断能源业务 |
| EI-07 | 系统集成数据同步 | 第三方↔平台 | HTTP/DB 等（由同步引擎适配） | 主数据/业务数据双向或单向同步（FR-INT） | 幂等、可重跑、连续失败告警 |
| EI-08 | 天气预报（调度域） | 外部天气源→平台 | HTTPS API | 调度预测所需天气数据 | 失败沿用前值并标注 |

## 4.3 回调报文兼容性要求

- 报文必须能无损映射为附录 B 的 StandardDataPoint；厂商扩展字段允许保留原始 JSON；
- 编码 UTF-8；时间支持 ISO-8601 或 epoch 毫秒（按数据源配置）；
- 平台对单报文大小、批量条数设上限并在联调文档中公布。

# 5. 数据需求

## 5.1 数据分类

| 类别 | 示例 | 存储 | 保留要求（默认，可按项目调整） |
| --- | --- | --- | --- |
| 主数据/档案 | 设备台账、表计、院区/分区、指标定义、组织 | MySQL 8.0 | 长期保存，逻辑删除 |
| 配置数据 | 回调凭证、映射规则、报警规则、价格策略 | MySQL（凭证加密） | 长期保存，版本化 |
| 业务数据 | 工单、巡检、出入库、订单、报表实例 | MySQL | 不少于 3 年 |
| 时序数据 | 电参量、设备指标、状态、能耗历史 | TDengine（开启时）/MySQL 降级表 | 高频明细 ≥1 年，聚合数据 ≥5 年 |
| 消息/死信 | 队列消息、死信原始报文 | RabbitMQ + MySQL/文件归档 | 死信 ≥180 天或至处理完毕 |
| 日志与审计 | 回调日志、登录/操作审计、安全日志 | MySQL/日志文件 | 审计 ≥6 个月（等保），关键操作 ≥1 年 |
| 文件数据 | 附件、报表、视频截图、3D 模型 | OSS | 随业务生命周期 |

## 5.2 时序数据要求

1. 同设备同指标同时间戳唯一，支持幂等写入；
2. 按时间分区/分表，支撑高频写入与时间窗查询；
3. 预聚合粒度：时/日/月，支撑大屏与报表快速读取；
4. TDengine 关闭时（`td.enabled=false`）使用 MySQL 时序表与聚合任务保证功能等价，性能指标可按部署规模另行约定；
5. 质量戳随数据点持久化，聚合默认仅取 GOOD。

## 5.3 数据质量与生命周期

- 入库前校验：类型、量程、时间合理性；异常数据标记而非丢弃；
- 未映射数据隔离区保留期限与重放机制（FR-HOSP-03/05）；
- 归档与清理任务由 XXL-Job 调度，按保留策略执行并留痕；
- 海外院区数据支持按合规要求配置留存周期与删除流程（数据最小化）。

## 5.4 数据隔离与备份

- 院区级逻辑隔离强制写入与查询条件；
- MySQL 定时备份、TDengine 按其备份策略；备份可恢复、定期演练；
- 敏感配置加密存储；导出行为受控并审计。

| NFR-PERF-01 | 回调吞吐 | 单集群接入层处理能力 ≥1000 TPS（数据点/秒），可水平扩展 | IOT 回调链路 |
| NFR-PERF-02 | 普通查询响应 | 常规列表/查询 P95 ≤1s（标准数据规模下） | 全平台查询类页面 |
| NFR-PERF-03 | 大屏首屏 | 医院大屏首屏完整渲染 ≤3s | 医院大屏/综合看板 |
| NFR-PERF-04 | 实时性 | 数据点从接收到可在监测页可见，正常情况下 ≤5s | 实时监测 |
| NFR-PERF-05 | 异步削峰 | 2 倍峰值持续 10 分钟不丢数、不雪崩，依赖队列缓冲 | 回调落库 |
| NFR-PERF-06 | 并发用户 | 支持不少于 200 并发在线用户常规操作 | Web 端 |
| NFR-PERF-07 | 报表 | 大数据量报表异步生成，10 万行级导出任务 5 分钟内完成并可下载 | 报表引擎 |

## 6.2 安全需求

| 编号 | 要求 |
| --- | --- |
| NFR-SEC-01 | 身份认证：Sa-Token + JWT；会话超时、失效与单点登可控 |
| NFR-SEC-02 | 授权：菜单/按钮/数据三类权限 + 院区级隔离；默认最小权限 |
| NFR-SEC-03 | 传输安全：全链路 HTTPS；MQTT 支持 TLS；回调 Token/IP/签名三选一以上、推荐全部启用 |
| NFR-SEC-04 | 密码策略：复杂度、定期更换、失败锁定；初始密码投产必须修改 |
| NFR-SEC-05 | 敏感数据：凭证/密钥加密存储；日志与导出脱敏；接口不返回敏感明文 |
| NFR-SEC-06 | 安全审计：登录、权限变更、鉴权失败、越权、导出、配置变更全部留痕，日志只增不改 |
| NFR-SEC-07 | 防护：防 SQL 注入/XSS/CSRF；接口限流；回调防重放、防伪造 |
| NFR-SEC-08 | 依赖安全：不引入存在高危已知漏洞且无修复方案的组件 |

## 6.3 可用性与可靠性

| 编号 | 要求 |
| --- | --- |
| NFR-REL-01 | 核心链路（回调接收—消息—存储—监测/报警）可用性 ≥99.9% |
| NFR-REL-02 | 数据可靠：回调失败可重试、死信可重放、可对账，承诺不丢数据 |
| NFR-REL-03 | RTO ≤30 分钟、RPO ≈0（通过消息持久化与补偿实现） |
| NFR-REL-04 | 接入层无状态可水平扩展；单点中间件故障不导致已接收数据丢失 |
| NFR-REL-05 | 降级：TDengine、视频、天气、短信等外部依赖故障时主功能可用并明确提示 |

## 6.4 可扩展性

- 设备、指标、院区、数据源均配置化接入，新增设备类别/厂商通过映射配置而非改代码；
- 接入层、消费层支持水平扩容；
- 医院模块与通用域解耦，新增行业包可参照同样加性模式扩展。

## 6.5 兼容性

- 服务端仅承诺 JDK 1.8 运行兼容；
- 浏览器兼容 Chrome/Edge 主流版本；大屏 1920×1080 起自适应；
- 与既有数据、接口、菜单、权限模型完全兼容，不产生破坏性变更；
- Vue3 演进版/uni-app 移动端通过接口契约保持数据兼容预期。

## 6.6 易用性

- 决策层页面操作层级不超过 3 级即可到达核心指标；
- 列表统一查询/导出/列设置规范；表单提供校验与错误指引；
- 关键流程（报警处置、工单、回调补偿）提供向导与批量操作；
- 培训后普通用户 30 分钟内可完成日常查询与处置操作。

## 6.7 国际化与本地化

- 框架支持中/英/俄/印尼，本期医院模块必达中文与英文；
- 多时区存储 UTC、按院区展示；报表标注时区；
- 单位体系可配置（公制优先），数值与货币本地化格式。

## 6.8 可维护性与可移植性

- 模块分包清晰、医院模块独立包与表前缀；配置外部化；关键链路有日志与监控埋点；
- 支持 Docker 化部署与中间件环境切换；数据库与中间件连接参数环境变量化；
- 提供部署/故障排查文档（参见 docs/部署指南 系列）。

# 8. 验收准则

## 8.1 总体准则

1. P0 需求 100% 实现并通过测试，不存在遗留致命/严重缺陷；P1 需求遗留缺陷有规避方案并经客户书面接受；
2. 每项 FR/NFR 至少对应一条测试用例（见《需求跟踪矩阵》与测试用例库）；
3. 在客户确认的标准数据规模与压测环境下达成第 6 章量化指标；
4. 既有业务域回归测试通过，证明加性开发未改变既有行为；
5. 完成部署文档、用户手册与运维交接。

## 8.2 关键验收场景（节选）

| 场景 | 验收点 |
| --- | --- |
| 回调接入 | 以 ≥1000 TPS 压测 10 分钟，接收数=入库数，无丢失；鉴权失败请求 100% 拒绝且有日志 |
| 可靠补偿 | 模拟 MySQL/TDengine/网络故障，消息重试与死信重放后数据完整、幂等无重复 |
| TDengine 关闭 | `td.enabled=false` 下监测、查询、报警功能可用 |
| 标准化 | 厂商报文全部映射为 StandardDataPoint；未映射数据进入隔离区并可补映射重放 |
| 医院闭环 | 设备越限报警→邮件/工单→处置→闭环统计链路贯通 |
| 能效评估 | 单位工作量能耗、排名、标杆结果可复算、可解释 |
| 多院区隔离 | 院区 A 用户无法以任何页面/接口看到院区 B 数据，越权有审计 |
| 国际化 | 中英文切换无硬编码遗漏；时间按院区时区展示 |
| 大屏 | 首屏 ≤3s，断网/部分数据异常时不白屏 |
| 合规 | 审计可追溯；无患者数据采集项；凭证加密 |

## 8.3 缺陷分级

致命（核心链路中断/数据丢失/安全绕过）、严重（主要功能不可用）、一般（功能异常有规避）、轻微（体验/文案）；致命与严重缺陷清零方可验收。

# 附录 B 标准数据点（StandardDataPoint）结构

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| pointId | String | 是 | 平台标准数据点唯一标识（可由来源+设备+指标+时间派生，用于幂等） |
| sourceCode | String | 是 | 数据源/IOT 平台编码 |
| campusCode | String | 是 | 院区编码（按凭证或映射确定） |
| deviceCode | String | 是 | 标准设备标识（由厂商设备标识映射得到） |
| metricCode | String | 是 | 标准指标编码（见 FR-HOSP-08） |
| value | Decimal/String | 是 | 指标值（已按单位换算归一） |
| valueType | String | 是 | 数据类型：NUMBER/BOOLEAN/STRING/ENUM |
| unit | String | 否 | 归一后单位 |
| ts | DateTime | 是 | 数据产生时间（ISO-8601，含时区；存储归一 UTC） |
| receiveTs | DateTime | 是 | 平台接收时间 |
| quality | Enum | 是 | GOOD / UNCERTAIN / BAD / MISSING |
| rawPayload | Text/JSON | 否 | 厂商原始字段保留（用于追溯） |
| workCondition | Enum | 否 | 工况：WORK/STANDBY/OFF/UNKNOWN（可由规则推断） |
| ext | Map | 否 | 扩展字段 |

**幂等键建议**：`sourceCode + deviceCode + metricCode + ts`（同周期聚合点按粒度对齐时间戳）。
