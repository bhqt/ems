## 1. 管理员职责与系统初始化清单

### 1.1 管理员职责边界

| 职责域 | 管理员负责 | 不负责/需协同 |
| --- | --- | --- |
| 账号权限 | 部门、岗位、用户、角色、菜单/按钮/数据权限 | 业务角色的权限范围由业务负责人书面确认 |
| 基础数据 | 字典、参数、公告、Logo、OSS、短信、邮件配置 | 业务阈值（报警、定额）由业务部门提需求 |
| 设备接入 | MQTT 账号、网关建档、IOT 回调 Token/签名/白名单、指标与映射、回调日志排障 | 现场布线、网关安装由自控/集成商完成 |
| 运行保障 | XXL-Job、日志、缓存、中间件状态、备份、应急 | 服务器/网络/数据库高可用由基础设施团队负责 |
| 安全合规 | 口令策略、最小权限、审计跟踪、默认口令整改 | 等保测评、制度发文由信息安全/院方负责 |

⚠️ 严禁管理员在生产库直接改业务数据；确需修正时先备份、走变更审批、保留 SQL 与回滚脚本。

## 2. 组织与权限管理

权限模型为标准 RBAC：**用户 → 角色 → 菜单/按钮权限**，并叠加**数据权限**与**院区隔离**。

**菜单路径**：**系统管理 → 部门 / 岗位 / 用户 / 角色**

### 2.1 部门管理

1. 进入 **系统管理 → 部门**，点【新增】。
2. 填写"部门名称、上级部门（形成院区→科室树）、显示顺序、负责人、联系电话、邮箱、状态"。
3. 医院建议结构：`XX医院（集团）→ 院区 → 后勤/设备/临床科室 → 班组`。
4. 部门停用后该部门下用户不能再作为新归属；删除前必须先转移用户，存在下级或用户时不允许删除。

> 📷 截图占位：部门树新增弹窗。

### 2.2 岗位管理

**系统管理 → 岗位**：新增"岗位名称、岗位编码（如 `energy_manager`）、顺序、状态"。一个用户可挂多个岗位，岗位用于人事归类与部分数据权限判断。

### 2.3 用户新增、编辑、删除

1. 进入 **系统管理 → 用户**，点【新增】。
2. 关键字段：

| 字段 | 填写要求 |
| --- | --- |
| 登录账号 | 全局唯一，建议工号或姓名拼音，不要用易混字符 |
| 用户姓名/手机号/邮箱 | 实名填写，手机号、邮箱用于报警与找回密码 |
| 归属部门 | 决定数据权限范围，务必选到最小正确科室 |
| 岗位 | 从岗位字典选择 |
| 角色 | 勾选一个或多个角色（取并集授权，慎用多角色叠加） |
| 状态 | 正常/停用 |
| 初始密码 | 临时强密码，勾选"首次登录强制改密" |

3. 编辑：行内【修改】可调整部门、角色、状态。
4. 删除：原则上**不删除离职用户**，改为"停用"，保留其操作日志与业务记录的实名归属。
5. 导入：可下载模板批量导入用户，导入后仍需逐人配角色。

### 2.4 忘记密码重置

1. **系统管理 → 用户**，找到该用户，点行内【重置密码】。
2. 设置临时强密码并口头/单独渠道告知本人（不要群发、不要贴群里）。
3. 勾选首次登录改密；如账号被锁定，可在用户编辑中清除锁定状态。
4. 管理员忘记自己密码：由另一名管理员重置；只有唯一管理员时，按应急流程在数据库侧处理（需审批+双人在场），处理后立即改密。

### 2.5 账号停用与强制下线

1. **停用**：用户编辑中"状态"改为停用并保存，该账号立即不能再登录。
2. **强制下线**：**系统管理 → 在线用户**，找到对应会话，点【强退】，其当前会话立即失效（用于离岗、账号异常、权限变更后即时生效）。
3. 权限调整后建议通知用户重新登录；涉及权限收缩时配合强退确保立即生效。

### 2.6 角色创建与授权（核心）

1. 进入 **系统管理 → 角色**，点【新增】：角色名称、角色编码（如 `hospital_energy`）、顺序、状态、备注。
2. **菜单权限**：在菜单树中勾选该角色可见的目录/菜单；**展开菜单节点可勾选按钮权限**（如 `system:user:add`、`:edit`、`:remove`、`:export`），按最小需要勾选。
3. **数据权限**：在角色列表点【数据权限】，五档范围：

| 数据范围 | 能看到的数据 |
| --- | --- |
| 全部数据 | 全院区/全部门（仅管理员、高层管理角色） |
| 本部门及以下数据 | 本部门 + 所有下级部门（科主任/院区管理员常用） |
| 本部门数据 | 仅本人所属部门 |
| 仅本人数据 | 只看到自己创建/负责的记录（普通操作员常用） |
| 自定义数据 | 在部门树中手工勾选可见范围（跨科室协同时使用） |

4. 保存后用该角色测试账号登录验证：菜单不多不少、按钮可见性正确、列表数据范围正确。

> 📷 截图占位：角色菜单权限树（含按钮节点展开）与数据权限五档单选弹窗。

### 2.7 多院区数据权限最佳实践

1. 顶层建立"院区"部门节点，院区下再挂科室。
2. 院区后勤人员：角色数据范围"本部门及以下"挂在院区节点 → 只看本院区。
3. 集团/院领导：单独角色"自定义"勾选多个院区或"全部数据"。
4. 医院大屏、检查检验设备、报警等所有医院数据均按院区过滤，**上线前务必用两个院区的测试账号交叉验证隔离性**。
5. IOT 设备绑定关系也归属院区，跨院区调拨设备时同步调整归属部门与绑定。

### 2.8 权限最佳实践清单

- 按"岗位模板角色"授权，不按人凑权限；新人入职直接挂模板角色。
- 禁止把 `admin` 超级管理员账号当公共账号；管理员各持实名账号并授管理员角色。
- `:export`（导出）、`:remove`（删除）权限单独评估后授予，敏感数据导出走审批。
- 每季度做一次权限复核：导出权限清单与在岗清单比对，离岗即停。
- 角色叠加取并集，出现"越看越多"先查该用户是否挂了多个角色。

## 3. 菜单管理

**菜单路径**：**系统管理 → 菜单**

### 3.1 菜单类型

| 类型 | 说明 | 典型内容 |
| --- | --- | --- |
| 目录 | 菜单分组容器 | 能耗分析、运维管理 |
| 菜单 | 具体页面 | 费用报表、维修工单 |
| 按钮 | 页面内操作权限点 | 新增/修改/删除/导出/导入 |

### 3.2 新增/修改菜单字段

| 字段 | 填写说明 |
| --- | --- |
| 上级菜单 | 选择挂载的目录/菜单 |
| 菜单类型 | 目录/菜单/按钮 |
| 菜单名称 | 显示名（中文）；多语翻译走国际化词条（见第 10 章） |
| 显示排序 | 数字越小越靠前 |
| 路由地址 | 前端路由 path，如 `hospital/screen`（医院大屏完整路由为 `/hospital/screen`） |
| 组件路径 | Vue 组件路径，如 `energy/cost/index` |
| 权限标识 | 按钮/接口权限串，约定 `模块:业务:动作`，如 `system:user:export` |
| 图标 | 从内置图标库选择 |
| 是否可见/外链/缓存 | 控制隐藏菜单、外链跳转、页签缓存 |
| 状态 | 正常/停用（停用即对所有角色不可见） |

### 3.3 操作步骤与注意事项

1. 新增页面菜单前先确认前端组件已发布，否则菜单点开会 404。
2. 按钮权限标识必须与前后端代码一致，改标识会导致按钮/接口 403。
3. 调整完菜单后让用户重新登录；自己测试可用无痕窗口。
4. ⚠️ 内置菜单（系统管理、医院模块等）不建议删除，需要隐藏用"停用"，避免升级冲突。

## 4. 字典、参数与通知公告

### 4.1 字典管理

**菜单路径**：**系统管理 → 字典类型 / 字典数据**

1. 字典类型：维护枚举分类，如 `alarm_level`（报警级别）、`device_type`（设备类型）、`energy_type`（能源种类）。
2. 字典数据：进入某类型点【详情/数据】，新增键值（value）、标签（label，中文显示）、排序、状态、CSS 样式（用于标签颜色）。
3. 业务页面的下拉选项、状态标签大多来自字典；新增枚举后各页面自动生效（必要时清缓存/重登）。
4. 已被业务数据引用的字典值不要删除，改停用即可；键值 value 一旦入库不要改。

### 4.2 参数配置

**菜单路径**：**系统管理 → 参数设置**

1. 以"参数键名/键值"维护系统级开关，如账号自助注册、用户初始密码、验证码开关、会话超时、登录失败锁定次数等。
2. 修改参数前先看备注说明，记录原值；改后点【刷新缓存】使其立即生效。
3. 与密码/会话相关参数按第 12 章安全基线设置，不要为了方便关闭验证码与锁定策略。

### 4.3 通知公告

**菜单路径**：**系统管理 → 通知公告**

1. 点【新增】，填标题、类型（通知/公告）、内容（富文本）、发布范围、生效时间。
2. 发布后用户登录后在首页/消息中心可见；置顶用于停机维护等重要通知。
3. 计划性停机提前 1～2 天发公告，写明影响范围、起止时间与联系人。

## 5. 基础配置

### 5.1 对象存储 OSS

**菜单路径**：**系统管理 → 对象存储（OSS）**（具体菜单名以版本为准）

1. 支持本地存储或云 OSS（MinIO/阿里云 OSS 等）。新增配置：服务商、endpoint、bucket、accessKey、secretKey、域名/访问前缀、路径规则。
2. 保存后点【测试连接/上传测试】，上传一个小文件并能访问/下载即为通过。
3. 附件（合同、MSDS、证书、工单照片、APP 拍照）全部走该存储，bucket 容量与生命周期策略纳入巡检。
4. ⚠️ accessKey/secretKey 属敏感信息，不入库明文传播；更换密钥时先在存储侧创建新密钥、系统侧切换、再废弃旧密钥。

### 5.2 Logo 与界面标识

**系统管理 → Logo（系统外观）**：上传登录页与顶栏 Logo（建议 PNG 透明底，尺寸按页面提示）；医院项目可上传院徽；替换后清浏览器缓存验证。

### 5.3 短信 SMS

1. 在短信配置中填写短信服务商、接入地址、AppKey/Secret、签名、模板编号。
2. 用测试手机号发送验证短信；报警短信与验证码可能使用不同模板/签名，分别报备审核。
3. 监控短信余量，余额不足提前充值，避免报警通知中断。

### 5.4 邮件

1. 配置 SMTP 主机、端口、发件账号、授权码/密码、加密方式（SSL/TLS）。
2. 点【测试】向自己发一封测试邮件；检查垃圾箱白名单与 SPF/DKIM 配置，防止报警邮件被判垃圾邮件。
3. 报警通知人在报警规则中选择，收件人邮箱以"用户管理"中的邮箱为准。

## 6. 设备接入配置

数据链路全景：

```
现场设备 ──MQTT──▶ EMQX ──▶ RabbitMQ ──▶ 消费者 ──▶ MySQL（业务/台账）
外部 IOT 平台 ──HTTP 回调(X-IOT-Token/X-IOT-Sign)──▶ 本系统 ──▶ TDengine（时序，可选）
```

### 6.1 MQTT 直采（EMQX）

1. 在 EMQX 控制台为本系统创建专用连接账号（用户名/密码），按主题（Topic）规划授权，遵循最小主题权限（只发布/订阅本项目前缀）。
2. 在平台 **设备管理 → 网关** 建档（网关编号与设备端配置一致），网关上送心跳与数据后查看"在线状态/最后心跳"。
3. 在 **设备管理 → 设备信息** 建档，设备编码与上报报文中的设备标识一致；完成网关/IOT 采集点绑定。
4. EMQX、RabbitMQ 默认口令必须修改；RabbitMQ 中确认消息队列有消费者、无持续堆积。
5. 排障顺序：设备是否通电联网 → EMQX 客户端是否在线、Topic 是否有消息 → RabbitMQ 队列是否堆积 → 消费者日志是否报错 → 库中是否落数。

### 6.2 外部 IOT 平台 HTTP 回调接入

**菜单路径**：**系统集成 → 接口配置**（配合"回调日志监控"页面与医院模块 IOT 绑定页面）

鉴权约定：回调请求必须携带请求头 **`X-IOT-Token`**（平台发放的接入令牌）与 **`X-IOT-Sign`**（用签名密钥对报文计算的签名），服务端校验通过才受理。

接入步骤：

1. **Token 发放**：在接口配置中新增一个接入方（IOT 平台/项目），系统生成接入方 ID 与 `X-IOT-Token`，登记使用方、联系人、用途。
2. **签名密钥**：为该接入方生成签名密钥（Secret），通过安全渠道（密封件/加密邮件）下发；首次联调后强制确认。支持密钥轮换：新建密钥 → 双密钥并行 → 对方切换 → 禁用旧密钥。
3. **IP 白名单**：登记对端出口 IP/网段，非白名单来源直接拒绝；在白名单页面维护变更。
4. **指标定义**：在指标字典中定义可接收指标（编码、名称、单位、数据类型），如 `power`（实时功率 kW）、`energy`（累计电量 kWh）、`status`（运行状态）。
5. **设备映射**：建立"IOT 平台设备编码 → 本系统设备/采集点"的映射（医院设备还需绑定到检查检验设备台账与院区）。
6. **联调**：对方按报文规范推送，平台在"回调日志监控"中返回成功；模拟器可用于没有真实数据时的演示与培训。

### 6.3 回调日志监控与排障

**菜单路径**：医院模块/系统集成中的"回调日志监控"

日志关键字段：接收时间、来源 IP、接入方、HTTP 状态、校验结果、报文摘要、处理结果/错误原因。

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 无任何日志 | 地址不通/对方未发 | 核对回调 URL（`/autoee-iot-ems` 前缀路径）、网络与防火墙 |
| 401/403 鉴权失败 | Token 错、签名错、时间戳/加密方式不一致 | 核对 `X-IOT-Token`、签名算法与密钥、前后空格与编码 |
| IP 拒绝 | 来源 IP 不在白名单 | 核实对方真实出口 IP 后加白 |
| 校验通过但无数据 | 指标未定义、设备映射缺失 | 补指标定义与设备映射后重放 |
| 数据落到错误设备 | 映射张冠李戴 | 修正映射，错误时段数据标记/重算 |
| 时有时无/延迟 | 对端限流、队列堆积 | 查 RabbitMQ 堆积与消费者实例数，必要时扩容 |

### 6.4 数据质量核查

1. 每日看：设备在线率、数据中断设备清单、回调失败率、队列堆积。
2. 对关键表计/设备配置"数据超时（如 15 分钟无数据）"提醒。
3. 定期核查：功率是否超量程、累计电量是否倒退、状态与功率是否自相矛盾。
4. 数据质量问题期间的统计数据要在报表中注明，避免错误考核。

> 更多接口字段与同步任务细节参见 `docs/用户手册/系统集成模块用户手册.md`。

## 7. 报警与通知配置

**菜单路径**：**报警管理 → 报警规则**

### 7.1 新建报警规则

1. 点【新增】，配置：
   - **适用对象**：全院/院区/设备类型/具体设备/表计/检查检验设备；
   - **报警项与判定**：指标（如功率、电流、待机时长、功率因数）、比较符（>/</区间/突变/无数据）、阈值上下限、持续时长/延时（防抖动）；
   - **报警级别**：紧急/重要/一般（决定颜色、通知范围与时限）；
   - **生效时段**：全天或自定义（如非工作时段待机报警）；
   - **恢复方式**：自动恢复或人工确认。
2. 保存后规则即参与实时判定，建议先用"观察模式/低级别"试运行数日再正式生效。

### 7.2 通知人与通知渠道

1. 在规则中勾选通知人/通知角色/值班组；通知方式勾选：站内消息、短信、邮件。
2. 值班组按 **运维管理 → 排班** 的当班人员动态通知，排班变更后通知自动跟随。
3. 邮件、短信发送前提是第 5 章渠道配置与测试通过。

### 7.3 工单联动开关

1. 规则中开启"自动生成维修工单"，设置默认派单班组与优先级；越限即自动建工单并关联报警。
2. 建议：紧急、重要报警开启联动；一般报警仅通知，避免工单泛滥。
3. 定期复盘"报警→工单"转化率与误报率，反向优化阈值与延时。

### 7.4 医院专属规则

检查检验设备建议配置：待机功率越限、连续待机超时、非工作时段运行、设备离线/无数据、单位工作量能耗异常等。规则归属院区，避免跨院区误告。

## 8. 定时任务（XXL-Job）

**入口**：调度中心控制台（XXL-Job Admin，地址由部署提供）；任务在平台菜单中可查看关联信息。

### 8.1 新增任务

1. 在 XXL-Job 控制台"任务管理"选执行器（EMS 业务执行器），点【新增】。
2. 填写：执行器、任务描述、JobHandler 名称（与代码一致）、**Cron 表达式**、路由策略、阻塞处理策略、超时与失败重试次数、告警邮件、负责人。
3. 典型任务：能耗小时/日/月统计、同比环比/定额计算、费用计算、报表生成、IOT 同步任务、数据清理、备份检查。
4. 保存后点【启动】，再点【执行一次】验证。

### 8.2 启停与日志

1. 【启动/停止】控制调度；【执行一次】用于手动补数（如昨日统计失败后重跑）。
2. 在"调度日志"查看每次触发的时间、参数、结果、耗时与异常堆栈。
3. 失败任务：先看日志异常 → 确认依赖服务（库/TDengine/接口）→ 修复后手动重跑 → 核对统计数据。
4. Cron 调整避开整点全员并发高峰；长耗时任务设置合理超时，阻塞策略选"丢弃后续调度"防叠加。

### 8.3 任务管理纪律

- 新增/修改任务走变更登记，注明用途、负责人、重跑影响。
- 不允许在生产直接跑"未评审的补数脚本"，防止统计翻倍。
- 每月检查失败任务清单，连续失败的任务必须有人认领。

| 菜单 | 看什么 | 典型用途 |
| --- | --- | --- |
| 系统管理 → 登录日志 | 登录成功/失败、IP、地点、时间、浏览器 | 查异地登录、暴力破解、排查登录问题 |
| 系统管理 → 操作日志 | 操作人、模块、动作（新增/修改/删除/导出）、请求参数、结果 | 审计误删/违规导出；日志只追加不允许普通管理员删除 |

### 9.3 缓存监控

**系统管理 → 缓存监控**：查看 Redis 内存、键数量、命中率；可查看缓存列表并在必要时**精确删除**某个缓存键（如字典/参数改后不生效）。⚠️ 不要无差别清空生产缓存，会造成瞬时数据库压力。

### 9.4 中间件与应用监控

1. **Spring Boot Admin**：查看应用实例健康状态、JVM 内存/线程、日志级别动态调整。
2. **RabbitMQ 管理台**：看队列消息数、消费者数、未确认消息；持续堆积立即排查消费者。
3. **EMQX Dashboard**：看连接数、订阅、消息吞吐；异常断连的客户端。
4. **MySQL/TDengine**：连接数、慢查询、磁盘水位（TDengine 数据增长快，重点看磁盘）。
5. JDK 注意：本系统强制 **JDK 1.8**；如以 JDK 9+ 启动必须加 `--add-opens` 参数，否则所有接口可能报 `InaccessibleObjectException` 返回 500（详见 `docs/部署指南/打包部署常见问题.md`）。

### 9.5 MQTT/RabbitMQ 监控菜单

平台内置的 MQTT/RabbitMQ 监控页可快速查看连接与队列概况，作为管理台的便捷入口；深度排查仍以中间件原生控制台为准。

## 11. 数据备份执行

### 11.1 备份对象

| 对象 | 内容 | 建议频率 |
| --- | --- | --- |
| MySQL `autoee_ems` | 全部业务与权限数据 | 每日全量 + binlog 增量 |
| TDengine | 时序数据（启用时） | 按官方策略每日/每周 |
| 附件存储 | OSS/本地附件目录（照片、合同、证书） | 每日增量，每周校验 |

| Redis | 以缓存为主，一般不备份；必要时备份持久化文件 | 按需 |

### 11.2 执行步骤（示例，以现场方案为准）

1. 在数据库服务器部署备份账号（仅备份权限）与定时任务，夜间业务低峰执行 `mysqldump --single-transaction --routines --triggers autoee_ems`。
2. 备份文件以"库名+日期"命名，gzip 压缩，**异机/异盘存放**，保留不少于 30 天，月度归档保留 12 个月。
3. 附件目录随文件备份策略同步；OSS 使用版本控制/跨区域复制。
4. 备份后自动检查文件大小与校验值，失败发告警（邮件/短信/值班群）。

### 11.3 恢复演练（必须做）

1. 每季度在隔离环境用最新备份恢复一次：建库 → 导入 → 启动应用连该库 → 抽查登录、台账、能耗数字、附件可下载。
2. 记录 RTO（恢复耗时）与 RPO（数据丢失窗口）是否满足业务要求。
3. **没有成功恢复演练过的备份等于没有备份。**

## 12. 安全合规

### 12.1 口令与账号策略基线

| 项 | 基线要求 |
| --- | --- |
| 默认口令 | admin/123456、数据库、Redis（`difyai123456`）、RabbitMQ、EMQX、OSS 密钥全部在上线前更换 |
| 口令复杂度 | ≥8 位，含字母与数字，建议含特殊字符；不得与用户名相同 |
| 改密周期 | 建议 ≤90 天；不得重复最近 3 次密码 |
| 失败锁定 | 连续失败 5 次锁定，锁定时长 ≥10 分钟（参数设置中配置） |
| 会话 | 闲置超时建议 30 分钟自动退出；敏感操作重新校验 |
| 账号实名 | 一人一号，禁止共享；离岗当日停用；外包账号设有效期 |
| 最小权限 | 菜单/按钮/数据权限按需授予，导出与删除从严 |

### 12.2 审计与留痕

1. 登录日志、操作日志保留不少于 6 个月（按等保/院方要求可延长）。
2. 重点审计：权限变更、导出、删除、报警规则修改、回调密钥变更、备份恢复操作。
3. 回调 Token/签名密钥、SMTP 授权码、OSS 密钥纳入保密台账，发放与轮换有记录。

### 12.3 数据与接口安全

1. IOT 回调必须同时校验 Token、签名与 IP 白名单，缺一不可；对外只暴露必要路径。
2. 生产启用 HTTPS（Nginx 证书），废弃 HTTP 明文登录。
3. 数据导出审批、脱敏（如联系人方式按角色脱敏）、导出日志可追溯。
4. 培训/测试环境使用 `hospital_seed_demo` 等脱敏数据，禁止拷贝真实生产数据到培训机。

## 13. 管理员 FAQ 与应急联系

### 13.1 管理员 FAQ

**Q1：新建用户登录后没有任何菜单？**
A：该用户未勾角色，或角色未勾菜单；检查用户角色、角色菜单权限，并让用户重登。

**Q2：用户反馈看不到本部门数据？**
A：查用户"归属部门"是否选对；查角色"数据权限"档位；多院区查院区节点归属；调整后强退重登。

**Q3：改了菜单/字典/参数，页面没变化？**
A：先让用户重登；参数/字典可在缓存监控中刷新或精确清除对应缓存键；浏览器强刷 Ctrl+F5。

**Q4：某接口/按钮返回 403？**
A：角色缺该权限标识（`模块:业务:动作`），在角色菜单树中勾选对应按钮；若是接口侧鉴权，核对权限串与代码一致。

**Q5：所有页面报"系统内部错误"/500？**
A：优先看是否 JDK 版本不对（必须 1.8；9+ 需 `--add-opens`）；再看应用日志、数据库连接、Redis、磁盘空间。

**Q6：回调全部 401？**
A：核对 `X-IOT-Token`、`X-IOT-Sign` 签名算法与密钥、对端时钟与编码；查看回调日志的具体拒绝原因。

**Q7：设备离线但现场说设备正常？**
A：依次查网关供电与网络、EMQX 连接与心跳、RabbitMQ 队列与消费者；外部 IOT 平台则查回调日志与白名单。

**Q8：定时任务突然不跑了？**
A：查 XXL-Job 调度中心执行器是否在线（应用与调度中心网络/时间同步）、任务是否被停止、Cron 是否被改、调度日志报错。

**Q9：误删了菜单/字典怎么办？**
A：若为逻辑删除可在库中恢复对应记录（先备份）；内置数据优先从同版本环境对照恢复；操作后清缓存验证。

**Q10：导出文件乱码或打不开？**
A：确认用 Excel 打开 UTF-8 的 xlsx；模板问题反馈实施；文件服务异常时看 OSS 配置与磁盘。

**Q11：用户被锁但急着用？**
A：用户管理中清除锁定并重置临时密码；同时看登录日志确认是忘密码还是暴力尝试，必要时强退全部会话。

**Q12：海外项目切换语言后出现 key 怎么办？**
A：缺翻译词条，登记 key 与上下文补 i18n 词条；不是数据错误，不影响业务。

**Q13：邮件收不到但测试能发？**
A：查规则通知人邮箱、排班是否为空、是否进垃圾箱；查看邮件发送日志与服务商限额。

**Q14：RabbitMQ 队列堆积怎么应急？**
A：先看消费者是否存活/报错恢复，必要时增加消费者实例；不要在未评估时直接清空队列（会丢数据）。

### 13.2 应急联系与分级

| 级别 | 场景示例 | 响应 | 联系人 |
| --- | --- | --- | --- |
| P0 系统不可用 | 全站无法登录、数据库宕机、生产数据被误删 | 15 分钟内响应，启动应急，必要时回滚/恢复备份 | 信息科值班 → 实施项目经理 → 研发支持（现场填写电话） |
| P1 核心功能受损 | 采集全断、报警不通知、XXL-Job 全失败 | 30 分钟内响应 | IOT 运维 / 实施顾问 |
| P2 局部问题 | 单设备无数据、个别账号异常、导出失败 | 当班处理 | 系统管理员 |
| P3 咨询优化 | 阈值调整、报表需求、词条补译 | 1～2 个工作日 | 系统管理员/业务负责人 |

应急操作纪律：先止损（停用、下线、切备用）→ 保护现场（日志、截图、备份）→ 通报 → 修复 → 复盘；**禁止在未备份的情况下直接改库"试一下"**。
