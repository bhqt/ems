## 1 用例编写规范

### 1.1 用例编号规则

`TC-模块码-序号（三位）`，例如 `TC-HCB-006` 表示医院回调模块第 6 条用例。编号一经发布不得复用；废弃用例保留编号并标注"已废弃"。

### 1.2 字段定义

| 字段 | 填写要求 |
| --- | --- |
| 用例编号 | 全局唯一，符合编号规则 |
| 优先级 | P0=核心主流程/验收必测；P1=重要业务与高频异常；P2=低频分支/界面/兼容 |
| 用例类型 | 正例、异常例、边界例（表中以"正/异/边"标注） |
| 前置条件 | 执行前必须满足的账号、数据、中间件、开关（如 TDengine enabled）状态 |
| 操作步骤 | 可按步骤复现，每步一个动作，含菜单路径或接口 |
| 测试数据 | 具体输入值、报文、文件、设备编码等 |
| 预期结果 | 可判定、可核对，包含页面表现、数据库结果、消息/文件结果、日志结果 |

### 1.3 通用前置条件

1. 测试环境中间件（MySQL8/Redis7.2/RabbitMQ3.12/EMQX5.3.2/TDengine3.x）健康，后端 8088（context-path `/autoee-iot-ems`）、前端 9029 可访问。
2. 已导入 `.dev/dumps/ems_full.sql` 与 `数据库脚本/hospital_seed_demo.sql`。
3. 默认管理员 admin/123456；普通测试账号按角色预置。
4. 医院回调用例默认具备：有效 X-IOT-Token、HMAC 密钥、测试机 IP 已加白名单；curl 造数模板由接口测试组维护。
5. MQTT 用例使用 `simulator/main.py`（单设备/压测模式）。
6. 用例执行结果记录为：通过 / 失败 / 阻塞 / 未执行；失败用例须关联缺陷单号。

## 22 用例执行说明

1. 每轮提测先执行冒烟集：TC-AUTH-001、TC-MQTT-001、TC-ALM-001、TC-ENG-001、TC-HCB-001、TC-HSCR-001、TC-DEV-001。
2. 与外部 IOT 平台联调前，TC-HCB 全量以 curl + 样例报文执行；联调后用真实平台报文对 P0 用例做一次回归。
3. TDengine 相关用例（TC-MQTT-001/008/009、TC-HCB-013 等）须分别在 TDengine 开启与关闭两种部署模式下各执行一轮。
4. 用例、缺陷、需求通过需求跟踪矩阵编号双向追溯；用例变更须评审并升版本。
