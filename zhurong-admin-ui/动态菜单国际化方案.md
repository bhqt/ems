## 二、架构设计

### 2.1 整体流程

```
后端返回菜单数据
    ↓
filterAsyncRouter 处理
    ↓
store 保存 routes
    ↓
Sidebar 组件渲染
    ↓
SidebarItem 组件处理单个菜单项
    ↓
computedTitle / computedOnlyOneTitle 计算标题
    ↓
translateMenuTitle 函数查找翻译
    ↓
查找语言文件 menu 配置
    ↓
显示翻译后的标题
```

## 三、使用说明

### 3.1 添加新菜单项翻译

1. 在 `src/i18n/lang/zh-CN.js` 的 `menu` 配置中添加中文翻译
2. 在其他语言文件中同步添加对应语言的翻译
3. 翻译的 key 应该与菜单项的原始标题一致（去掉空格和特殊字符）

### 3.2 支持的菜单查找路径

`translateMenuTitle` 函数会按以下顺序查找翻译：

1. 如果标题包含 `.`，直接作为 key 查找
2. 尝试 `menu.{标题}`
3. 尝试 `menu.{模块}.{标题}`（遍历所有已知模块）
4. 尝试 `common.{标题}`
5. 返回原始标题作为 fallback

## 四、语言切换实现

### 4.1 响应式更新

菜单标题通过计算属性实现响应式更新：

```javascript
computed: {
  ...mapGetters(['language']),
  computedTitle() {
    // 通过获取 this.language 建立响应式依赖
    const _ = this.language
    return translateMenuTitle(this.item.meta.title, this.item.meta.title)
  }
}
```

当语言切换时，`this.language` 变化会触发计算属性重新计算，从而实现菜单标题的即时更新。

### 4.2 语言切换流程

1. 用户点击语言选择
2. `loadLanguageAsync` 加载语言包
3. `app/setLanguage` 更新 store 中的 language 状态
4. 计算属性检测到 language 变化
5. 重新计算并显示新语言的菜单标题

## 五、后端集成建议

### 5.1 方案一：后端返回国际化 key（推荐）

后端返回的菜单数据中，`meta.title` 使用国际化 key：

```json
{
  "path": "/system/user",
  "meta": {
    "title": "menu.system.user",
    "icon": "user"
  }
}
```

优点：
- 不需要查找匹配，直接翻译
- 逻辑简单，性能好
- 前后端职责清晰

### 5.2 方案二：后端返回原始文本（当前方案）

后端返回中文标题，前端通过 `translateMenuTitle` 查找匹配：

```json
{
  "path": "/system/user",
  "meta": {
    "title": "用户管理",
    "icon": "user"
  }
}
```

优点：
- 后端无需改动
- 兼容性好

缺点：
- 需要维护标题到 key 的映射
- 查找匹配有一定性能开销
